PostgreSQL EXPLAIN ANALYZE 解析報告

結論

PostgreSQL 的 EXPLAIN 與 EXPLAIN ANALYZE 是資料庫效能調優中不可或缺的工具，但兩者在行為與副作用上有本質的差異。EXPLAIN 僅用於預覽查詢計畫（Query Plan），不會實際執行 SQL；而 EXPLAIN ANALYZE 會實際執行查詢並回報真實的執行統計數據。對於涉及資料變更的 DML 操作（如 INSERT、UPDATE、DELETE），使用 EXPLAIN ANALYZE 會導致資料庫產生實際變更，因此在生產環境中必須謹慎使用，通常建議配合事務（Transaction）進行測試。

核心主張

  1. 執行行為差異：

- EXPLAIN：僅由規劃器（Planner）產出預估計畫，包含預估成本（Cost）與預估列數（Rows）。

- EXPLAIN ANALYZE：實際執行 SQL。除了顯示計畫外，還會提供真實的執行時間（Execution Time）、實際列數（Actual Rows）與循環次數（Loops）。

  1. DML 操作的副作用與保護：

- 使用 EXPLAIN ANALYZE 執行 INSERT、UPDATE、DELETE、MERGE 或 CREATE TABLE AS 等語句時，資料庫會產生實際的副作用。

- 安全實踐：為了在不影響資料的情況下觀察這些操作的執行計畫與統計，必須將語句包裹在事務中，並在結束前回滾：

```sql

BEGIN;

EXPLAIN ANALYZE UPDATE ...;

ROLLBACK;

```

  1. 進階分析功能：

- BUFFERS：當配合 ANALYZE 使用時，可顯示共享區塊（Shared Blocks）的命中（Hit）、讀取（Read）、髒資料（Dirtied）與寫入（Written）數量，對於分析 I/O 性能至關重要。

- FORMAT JSON：可將輸出轉換為 JSON 格式，方便透過程式（如 Python 或 Node.js）解析並進行自動化效能監測。

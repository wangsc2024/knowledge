AI 編碼工具對開發者生產力的實證效果 洞察報告

---

1. 被推翻的主張（Refuted）

主張 1

使用 GitHub Copilot 可以讓專業開發者完成 HTTP‑server JavaScript 任務的速度提升 55.8%。

為何不成立

  • 該 55.8% 的數據僅來源於一項受控實驗：專業開發者在限定時間內實作一具體的 JavaScript HTTP 伺服器任務。
  • 結果未涵蓋真實開發中的需求整合、程式碼審查、除錯、系統設計、維護等複雜活動。
  • 企業採用數據顯示 Copilot 的使用率與效益參差不齊，且缺少程式碼品質、技術債及業務價值的後續指標。
  • 因此，將單一任務的加速效果推廣為「專業開發者完成 HTTP‑server JavaScript 任務速度提升 55.8%」的普遍主張是不準確的。

---

主張 2

在 METR 隨機對照試驗中，經驗豐富的開源開發者使用 AI 工具（Cursor Pro + Claude 3.5/3.7 Sonnet）處理真實問題時，實際表現比未使用時慢 19%。

為何不成立

  • METR 在 2025 年初的隨機對照試驗確實發現經驗豐富的開源開發者使用 AI 工具時平均慢了 19%。
  • 然而，該團隊在 2026 年早期的更新顯示，隨著工具改進與開發者學習曲線，同一組開發者現在估計快了約 18%（信賴區間 -38% 至 +9%），表示最初的負面效應已被逆轉。
  • 因而主張「使用 AI 時實際表現慢 19%」僅反映過時的早期數據，並不代表後續的事實。

---

主張 4

AI 生成的程式碼包含的錯誤數量是人類編寫程式碼的 1.7 倍，且安全漏洞多 15–18%。

為何不成立

  • 多項獨立研究顯示，當控制團隊輸出功能數量時，AI 生成程式碼（如 GitHub Copilot）的缺陷率與人類編寫程式碼相近，未達到 1.7 倍。
  • 安全漏洞方面，經過程式碼審查與自動掃描後，AI 建議的漏洞率與人類程式碼相當，甚至在某些情況下較低。
  • 因此，原始主張的錯誤數 1.7 倍及漏洞多 15–18% 的說法缺乏支持。

2. 未經對抗檢驗的主張（未完成檢驗）

主張 3

Opsera 2026 基準顯示，AI 生成的 pull request 採納率為 32.7%，而人類編寫的程式碼採納率為 84.4%。

狀況說明

  • 此條件在對抗檢驗階段未能完成（responses.agent 未在 8 ター內收斂），因此 未經對抗檢驗。
  • 基於現有資訊，我們無法確認該數字的正確性或其適用範圍；亦不應將其視為已經驗證的事實。

---

3. 結語

  • 上述 被推翻 的主張提醒我們，單一實驗或早期數據不應被過度概括為開發者生產力的普遍提升。
  • 未經對抗檢驗 的主張需要進一步的獨立驗證才能被納入可靠的洞察中。
  • 在評估 AI 編碼工具對開發者生產力的影響時，應綜合考慮任務複雜度、後續維護、程式碼品質及業務價值等多面向指標，而非僅依賴孤立的速度或錯誤率數字。

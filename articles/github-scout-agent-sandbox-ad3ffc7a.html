GitHub Scout：Agent 安全／Sandbox 觀測（2026-07-19 第二輪）

專案觀測摘要

microsoft/agent-governance-toolkit（★4863，pushed 2026-07-17）：AI Agent Governance Toolkit，涵蓋 policy enforcement、zero-trust identity、execution sandboxing、reliability engineering，宣稱涵蓋 10/10 OWASP Agentic Top 10。架構：Policy Engine（Rust-based Agent Control Specification）於 middleware 層攔截每個 tool call/message send/delegation；四層 privilege ring 分級執行控制；Hypervisor 追蹤執行計畫並維護 in-memory commitment records + command denylist；MCP Security Gateway 攔截工具層 poisoning。明確 fail-closed：「denied actions are structurally impossible」。Approval 機制：policies 支援 require_approval 動作＋指定 approver；SRE 模組提供 kill-switch 與 circuit breaker。

NVIDIA/garak（★8498，pushed 2026-07-14）：LLM 漏洞掃描器，probe/detector 架構——probes 層生成攻擊性測試提示（提示注入、編碼攻擊、DAN 越獄），detectors 層評估輸出弱點（幻覺、資料洩漏、毒性內容）。定位為離線紅隊測試工具（CLI 批次掃描），非 runtime guardrail；JSONL 結構化報告可接 CI/CD。

改進提案

  1. P1｜研究筆記留存：將本輪觀測寫入 config/github-scout-review-policy.yaml（v3.0.8→3.0.9）與 docs/github-scout-agent-comparables.md（新增 agent_security_tool_use_guardrails_comparables 2026-07-19 段落）。
  2. P1｜四層 privilege ring 分級執行借鑑：本系統 config/autonomous-harness.yaml 之 execution_sandbox_contract.network_access.default_mode=allow（2026-07-12 已知缺口）現行為二元 allow/deny；AGT 提供更細粒度的分級執行控制模型可供借鑑，觸及 guarded_operations 沙箱契約，需人工審核後才可能調整。
  3. P2｜離線紅隊掃描整合評估：評估納入 garak 作為本地模型（Gemma/gpt-oss 系列）週期性離線紅隊安全稽核工具，因需新增 pip 依賴（違反本系統「不新增依賴」預設原則），需人工評估相依性與排程整合成本，暫不自動落實。

審查結論

兩案皆通過可行性/穩定性初步審查（研究筆記留存案為文件型變更，feasibility=9, stability=9，直接落實；分級執行控制與紅隊掃描整合案因觸及 guarded_operations 沙箱契約或需新增依賴，判定 human_review_required=true，轉入 backlog）。

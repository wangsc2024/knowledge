PostgreSQL EXPLAIN ANALYZE 解析報告

結論

PostgreSQL 的 EXPLAIN 與 EXPLAIN ANALYZE 在執行機制上有本質差異。EXPLAIN 僅用於產生查詢計畫（Query Plan）並預估執行成本，不會實際執行 SQL；而 EXPLAIN ANALYZE 會實際執行查詢，並回報真實的執行時間與統計數據。

對於涉及資料變動的語法（如 INSERT、UPDATE、DELETE），使用 EXPLAIN ANALYZE 會產生實際的資料修改。為了在不影響生產環境資料的情況下獲取這些資訊，官方建議將指令包裝在 BEGIN; ...; ROLLBACK; 區塊中。

此外，若需深入分析 I/O 效能，應搭配 BUFFERS 選項使用，並透過 FORMAT JSON 輸出，以便於後續程式解析與視覺化。

核心主張

  1. 執行差異：EXPLAIN 是預估，EXPLAIN ANALYZE 是實際執行。
  2. 副作用防範：執行 INSERT/UPDATE/DELETE 時使用 EXPLAIN ANALYZE 必須配合事務處理（Transaction），以防止資料被永久修改。
  3. 效能深度監控：BUFFERS 是觀察緩存命中與實際 I/O 的關鍵參數。
  4. 工具整合：使用 FORMAT JSON 是將資料餵給分析工具（如 pg_stat_statements 或自定義腳本）的最佳實踐。

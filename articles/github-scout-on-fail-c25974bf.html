GitHub落實方案系統改進on_fail 分級失敗策略Hook/Guard

GitHub Scout 落實方案：guardrails-ai on_fail 分級失敗策略引入品質閘門

風險等級：high（待人工審核）

來源：guardrails-ai/guardrails（REST 觀測 7127★，pushed 2026-07-10）

計畫檔：docs/plans/github-scout-20260712-guardrails-onfail-quality-gate.md

目標

  1. 為 tools/report_quality_lint.py 定義可選 on_fail 分級詞彙（exception/reask/filter/fix/refrain/noop）。
  2. 評估 Phase 2 結果驗證失敗（F 等）時觸發有界 1 次 reask，而非直接判定失敗。
  3. 明確排除套用至三個核心攔截 hook。

風險評估

  • reask 迴圈若無上限保護，可能與既有 validate_results 重試機制疊加造成多層延遲。
  • 重試 prompt 設計不當可能導致 Agent 只改寫措辭規避 lint 規則。
  • 涉及 Phase 2 timeout 預算，需先跑 timeout-remediation workflow 對照評估。

Rollback

Phase 1：移除 --dry-run-reask 旗標（無副作用）。

Phase 2：feature flag 預設 off，退回現行二元 F 等判定。

驗證方法

  1. uv run pytest tests/tools/test_report_quality_lint.py -v
  2. 對近 30 天 F 等歷史結果檔重放 --dry-run-reask，人工抽查 10 筆後決定是否啟用

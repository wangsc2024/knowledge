大型語言模型的知識蒸餾

摘要

知識蒸餾（Knowledge Distillation, KD）源自 Hinton 等人 2015 年提出的「暗知識」概念，如今已從單純的模型壓縮技術，演化為大型語言模型（LLM）能力轉移、合成資料生成與地緣政治角力的關鍵槓桿[G2]。學術界正發展統一理論框架解釋蒸餾的內在機制[G3][G4]，產業界則以 DeepSeek R1 蒸餾系列驗證其威力[G2]，但也有分析指出蒸餾效益「鋸齒化」，在 RL 主導的前沿競賽中難以完全取代大規模算力投入[G1]。

背景與現況

知識蒸餾的技術根源可追溯至 2015 年 Google 研究者 Hinton、Vinyals 與 Dean 發表的〈Distilling the Knowledge in a Neural Network〉。該論文指出，大型「教師」模型輸出的機率分佈中，除了最高分的正確答案外，其餘接近零的小數值（例如「貓」以外「老虎」「獅子」的殘餘機率）同樣蘊含結構性知識，稱為「暗知識」（dark knowledge）；讓體積較小的「學生」模型模仿這種完整的軟標籤分佈，能比單純學習硬標籤（正確答案）吸收更多資訊[G2]。

進入 LLM 時代後，蒸餾的定義大幅擴張。它不再只是「壓縮一個模型」，而更接近「用算力把教師模型的部分能力轉成資料資產，再讓學生模型去學」——具體操作包括直接使用強模型的輸出訓練弱模型、大量生成合成資料（synthetic data）用於後訓練，以及針對推理、Agent 行為、工具調用等特定能力進行「能力搬運」[G1]。一份完整的學術綜述將這套流程系統化為「算法（algorithm）—技能（skill）—垂直領域（verticalization）」三大支柱，涵蓋指令遵循、多輪對話、對齊（思考模式、偏好、價值觀）、Agent（工具使用、規劃）、自然語言理解與生成、程式碼等技能維度，以及法律、醫療、金融、科學等垂直應用[G6][G7]。

產業層面，DeepSeek 於 2025 年發佈 6,710 億參數的混合專家模型 R1，同時釋出從 1.5B 到 70B 共七種規模的蒸餾版本；其中 7B 蒸餾模型在數學推理基準上擊敗了 OpenAI 的 o1-mini，震撼業界[G2]。與此同時，Anthropic 指控多家中國實驗室透過大規模 API 請求「竊取」Claude 的知識用於訓練自家模型，OpenAI 也向美國立法者提交公開信要求立法限制，使蒸餾從純技術問題升級為中美 AI 競爭與合規爭議的焦點[G1][G2]。

機制與技術分析

蒸餾的核心技術機制建立在「軟標籤」與「溫度縮放」（temperature scaling）之上。標準輸出使用 softmax 函數將內部計算值轉為機率分佈：低溫度下輸出尖銳（近乎 one-hot），高溫度下輸出平滑（各選項機率更均勻）。訓練蒸餾時刻意調高溫度，讓教師模型的軟標籤充分展露暗知識；待學生模型部署推論時再降回低溫，輸出精確答案。這種「訓練時高溫、推論時低溫」的設計，是暗知識得以有效傳遞的技術核心[G2]。

在方法論層面，白盒（white-box）蒸餾可直接利用教師模型的預測分佈，透過 KL 散度（Kullback-Leibler Divergence）等分佈層級目標訓練學生逼近教師輸出；黑盒（black-box）蒸餾則只能取得教師生成結果，多透過監督微調（SFT）進行[G3]。最新研究進一步指出，散度方向、優化策略與資料機制三個設計軸線相互交織、缺一不可：前向 KL（Forward KL）促進「模式覆蓋」但易產生過於平滑的預測；反向 KL（Reverse KL）強調「模式尋找」，但師生能力差距過大時訓練不穩定；資料機制上，離策略（off-policy）蒸餾依賴外部資料但常有訓練—推理行為失配，在策略（On-Policy Distillation）則從學生自身採樣 rollout，能對齊訓練分佈卻帶來額外運算開銷。為兼顧兩者，Hybrid Policy Distillation（HPD）提出將散度重新表述為 token 層級的重新加權對數似然（reweighted log-likelihood）目標，並用負 $K_1$ 估計器同時處理離策略與學生採樣 token，在數學推理、對話、程式碼任務上驗證了優化穩定性與效率的提升[G3]。

另一條理論路線試圖回答「蒸餾究竟在學生模型內部做了什麼」。有研究將 LLM 的輸出分數分解為大量「互動」（interaction，即輸入變數間的非線性關係組合），發現所有 KD 方法共通的機制是「互動稀疏化」——學生模型在推理時只保留少量互動，其餘效果被抑制為零；而不同蒸餾方法之間的效能差異，主要來自處理「複雜互動」（涉及更多輸入變數的高階非線性關係）的能力差異：越能讓學生模型減少對複雜互動的依賴，效能通常越好。據此提出的「複雜互動懲罰」（Complex Interaction Penalty, CIP）損失函式，作為即插即用模組整合進現有 KD 方法後，能持續提升域內與分佈外基準表現[G4]。

值得釐清的是，知識蒸餾與廣義的「模型壓縮」並非同一件事：模型壓縮涵蓋剪枝（pruning，將部分權重置零以稀疏化）、量化（quantization，降低權重與啟用值的數值精度）、低秩分解（low-rank decomposition，用 $W \approx UV^T$ 近似權重矩陣）等技術，操作對象是「同一個模型的參數」；而知識蒸餾是訓練一個全新的、較小的學生模型去模仿教師模型的輸入輸出行為，並不使用教師模型的訓練參數或訓練目標本身[G8]。實務上兩者常被合併使用——例如「先訓大、再壓縮」（train big, then compress）範式：先用較少訓練步數訓練一個大模型，再大幅壓縮，研究發現同等算力預算下此法優於直接訓練輕量小模型；Deep Compression 則示範了「剪枝→量化→霍夫曼編碼」三步流程可在 AlexNet 上達到 35 倍壓縮比[G8]。

在實際效果上，蒸餾呈現高度「鋸齒化」（jagged）的特性：某些任務上少量高品質合成資料就能帶來大幅提升，但也常見「餵入更多教師輸出、學生表現反而變差」的情況，原因包括教師與學生預訓練分佈的能力錯配、大規模合成資料帶來的標註噪音與風格漂移，以及與原始語料混排比例失衡[G1]。這意味著蒸餾早已不是「越多越好」的線性疊加，而是一個需要精細設計 Prompt 模板、教師組合與消融實驗的研究型工程問題[G1]。

應用與實務啟示

對於資源有限的團隊，蒸餾提供了繞過算力瓶頸的捷徑：租用或呼叫他方 API 遠比取得大量實體 GPU 容易，且屬按需付費、可快速迭代[G1]。這也是為何蒸餾技術在演算法層面持續精進——多教師蒸餾（結合多個教師模型以提升穩健性）、Prompt 蒸餾（將冗長提示壓縮為精簡版本）、特徵層蒸餾（對齊教師與學生的隱藏層表示，而非僅比對輸出 logits）、資料增強（用教師生成的樣本擴充訓練資料以改善泛化）等技巧，都已成為工程實務中的標準工具箱[G5]。在技能維度上，蒸餾已被系統性應用於指令遵循、多輪對話、RAG 能力、對齊（思考模式與偏好）、Agent 的工具使用與規劃，乃至法律、醫療、金融等垂直領域模型的建構[G6][G7]。

對於規劃自建模型的團隊，值得注意的實務建議包括：其一，先明確蒸餾的目的——是提升特定任務（程式碼、Agent、工具編排）、改善整體對話對齊，還是單純為了壓縮模型降低推理成本，不同目標需要完全不同的蒸餾設計與評估指標；其二,把蒸餾當作研究專案而非簡單工程任務，需要多樣化 Prompt 模板設計、多教師組合探索,以及嚴格的 A/B 測試與消融實驗,避免「越學越糟」;其三,蒸餾不應與 RL、SFT、預訓練割裂思考,而應納入同一整體設計,決定哪些能力適合蒸餾打底、再交由 RL 微調[G1]。CIP 損失函式這類即插即用模組的出現[G4],也顯示蒸餾正從「經驗式調參」走向有理論支撐、可被系統化改進的工程方法。

觀點與趨勢判讀

材料中存在一個值得正面裁定的張力：G2 呈現的 DeepSeek 案例，展示蒸餾能以極低成本（相對於從頭訓練）複製出逼近頂尖模型的能力，7B 學生模型甚至在特定基準上超越更大的 o1-mini；而 G1 則主張，蒸餾量級再大，終究只是後訓練階段的一部分，前沿實驗室在預訓練與 RL 上投入的總算力遠超蒸餾資料規模，且當前沿模型越來越依賴大規模線上強化學習（RL 生成成本主導、且訓練必須基於「正在訓練的模型本身」的 on-policy 資料）時，外部 API 蒸餾能提供的多是離線輔助訊號，難以複製教師模型完整的能力結構。這兩者並不矛盾，而是描述了蒸餾效益的兩個不同層次：蒸餾在「後訓練 / 特定任務追趕」上可以是高槓桿、高性價比的捷徑（DeepSeek 案例是明證），但在「前沿能力的原創性突破」上，蒸餾更像是放大器而非替代品——若基礎預訓練與 RL 基礎設施不夠扎實，蒸餾的收益也無從放大[G1]。換言之,「中國模型靠蒸餾追平美國」是一種過度簡化的敘事,效率提升是被算力限制倒逼出的工程優勢,而非蒸餾本身的魔法[G1]。

技術演進的方向也印證了這個判讀：學界正從「怎麼蒸餾」轉向「為什麼蒸餾有效」的理論化階段——HPD 統一了前向/反向 KL 與在/離策略資料的設計空間[G3],互動稀疏化理論則從模型內部機制解釋了跨方法的效能差異根源[G4]。這種理論化趨勢預示蒸餾將從「大量調用教師 API 做合成資料」的粗放模式,轉向更精細的、可解釋、可調控的訓練組件。同時,Anthropic 與 OpenAI 對蒸餾行為的法律與政策施壓[G1][G2]顯示,蒸餾的技術門檻雖低（一台電腦、一批問題、足夠耐心即可執行）,但其合規邊界仍高度不確定,依賴外部 API 蒸餾的策略未來將面臨更多法律與供應鏈政治化的風險,這對任何嚴肅的模型研發者而言都是必須納入的長期變數[G1]。

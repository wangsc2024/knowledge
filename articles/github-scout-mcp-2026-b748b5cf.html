官方治理模型精確化（WebFetch modelcontextprotocol.io/registry/about）：

  1. 由 Anthropic／GitHub／PulseMCP／Microsoft 共同背書
  2. namespace 認證＝reverse-DNS 格式（如 io.github.user/server）綁定 GitHub／DNS／HTTP challenge 三種驗證方式證明所有權
  3. 明文聲明安全掃描完全委由下游——底層套件登錄（npm/PyPI/Docker Hub）與下游 aggregator/marketplace 各自負責掃描，官方 Registry 本身不做安全掃描
  4. codebase 明言非為自架設計，fork 需自行維運
  5. 反垃圾機制：字元限制＋正則驗證＋人工下架；AI-based 偵測與社群回報列未來規劃
  6. 現仍標示 preview 狀態，可能有 breaking change

次要發現：MCP 規範 2026-07-28 發布 Release Candidate，新增 SEP（Specification Enhancement Proposal）正式提案制管理功能廢棄/移除之 Feature Lifecycle Policy。

審查結論

  • 官方 Registry（身份層）與 docker/mcp-registry（07-20 觀測，內容安全層）形成明確二層分離模型；對照本系統三核心攔截 hook 屬內容/行為層防護，本系統單一操作者本機架構無發布者身份驗證概念，關聯性低，僅觀察不建議引入
  • SEP 正式提案制治理對照本系統 workflows/index-lifecycle-closed-loop-workflow.yaml 現行機械化 value_score prune 機制，因治理規模不對等（多方組織協作 vs 單一操作者），本輪結論不建議引入

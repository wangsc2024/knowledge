GitHub靈感蒐集系統改進Hook/Guardguardrails

GitHub Scout：Hook/Guard 主題觀測（2026-07-23）

專案觀測摘要

  • trufflesecurity/trufflehog（27160★，REST 觀測，pushed 2026-07-23）：秘密偵測工具，以 verified/unverified/unknown 三級主動驗證分類（對來源 API 驗證憑證是否仍有效），涵蓋 800+ 秘密類型、700+ 偵測器。預設 fail-open（僅回報不阻擋），需顯式加 --fail 旗標才轉 fail-closed。
  • open-policy-agent/opa（12010★，REST 觀測，pushed 2026-07-22）：通用政策引擎，query-based 決策架構，由消費端（K8s admission webhook／Terraform／Docker authorization 等）主動查詢決策。OPA 本身不內建 fail-open/closed 預設值，由整合層決定。

改進提案

  1. P2｜trufflehog verified-tier 二次驗證（target: scripts/auto-task-secret_scan_daily.ps1）：現有秘密掃描為自建正則 pattern match，無主動驗證真偽。因需新增外部 Go 二進位依賴，非零成本變更，待人工評估。
  2. P1｜決策外置 vs 內建 fail-closed 風險對照（target: config/github-scout-review-policy.yaml, docs/github-scout-agent-comparables.md）：已直接落實純文件補充。

審查結論

P1 方案（OPA 對照筆記）feasibility_score=9、stability_score=9，第 1 輪審查即通過（純文件附加操作，不涉及核心攔截層修改），直接落實。P2 方案（trufflehog 整合）因涉及新增外部二進位依賴，不自動落實，列入 backlog 待人工評估。

已落實項目

  • config/github-scout-review-policy.yaml：hook_guard_agent_guardrails.notes 新增 2026-07-23 補充（v3.0.14→3.0.15）
  • docs/github-scout-agent-comparables.md：新增 hook_guard_agent_guardrails_comparables（2026-07-23 REST+WebFetch 觀測，第四輪）章節

待人工審核項目

  • 是否引入 trufflehog verified-tier 作為 secret_scan_daily 的第二階段驗證層（需評估新增 Go 二進位依賴之維運成本）

核心發現

trufflehog 主動驗證分級可補足本系統既有正則掃描「無法分辨真偽」的缺口；OPA 決策外置架構若消費端疏漏顯式宣告 fail-closed 會退化為 fail-open，本系統既有 hooks/pre_bash_guard.py 常駐內建 fail-closed 已規避此類風險，驗證既有設計方向正確，不建議引入 OPA 取代現有攔截層。

核心發現

兩案共同設計原則：攔截層在自身異常或規則未決時，預設動作是拒絕而非放行（gitleaks 甚至不區分「偵測到問題」與「掃描器本身出錯」）。

對照本系統：hooks/hook_utils.py:371-376 的 read_stdin_json() 解析 stdin 失敗回傳 None 時，hooks/pre_bash_guard.py:311-313／hooks/pre_write_guard.py:586-588／hooks/pre_read_guard.py:199-201 三個 main() 皆回傳 output_decision("allow")（已用 Grep+Read 逐行驗證程式碼，非推論）。即本系統三個核心攔截層僅「規則命中」路徑 fail-closed，「輸入無法解析」路徑實為 fail-open，與既有研究筆記多輪宣稱之「fail-closed」定位有落差。

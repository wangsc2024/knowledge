GitHub Scout：自癒系統 2026-07-20

專案觀測摘要

  • robusta-dev/robusta（REST 3057★，pushed 2026-07-19）：Kubernetes 告警平台，規則型 pattern match 為主，可選整合 HolmesGPT 補 LLM 根因分析；宣告式 auto-remediation rules 支援 team/namespace 條件路由；預設 fail-open 自動執行，無 approval gate 或 dry-run 揭露。
  • StackStorm/st2（REST 6501★，pushed 2026-07-17）：事件驅動自動化平台（IFTTT for Ops），Sensor→Trigger→Rule 條件比對；160+ packs、6000+ actions；支援 Workflow 內嵌 Approval Gate（ChatOps 核准），為本輪唯一具「多步驟工作流程中途暫停待核」機制者。
  • 兩案皆非 2026-07-16 已複核之 keep/k8sgpt/agent-orchestrator，本輪刻意擴大模式覆蓋面。

改進提案

  1. P2：StackStorm 式 workflow 中途 Approval Gate — 本系統 self_heal 修復動作皆為單步 Edit+驗證+rollback，非多步驟 workflow，暫無直接適用場景，列長期觀察。
  2. P2：Robusta 式「規則優先＋LLM 根因分析為可選增益層」— 可比照在 tools/failure_recovery_router.py 的 find_default fallback 路徑（無 task-specific 規則命中時）附加一行 LLM 假說供人工參考，不改變既有確定性派工邏輯；因觸及核心自癒派工工具，需人工評估。

審查結論

兩項提案皆評為 risk_level=medium（涉及 self_heal 核心工具/config），feasibility_score=7、stability_score=6（缺明確 rollback 驗證步驟與導入時機證據），未達步驟 8 自動落實門檻（需 stability≥7），標記 status=needs_human_review，不自動落實程式碼變更。

GitHub Scout 研究筆記：自癒系統（self_healing_systems）

專案觀測摘要

本輪 REST 即時觀測（api.github.com）3 個開源自癒/AIOps 專案：

  1. keephq/keep（12,020★，pushed 2026-07-06）— 開源 AIOps 告警管理平台。診斷模型為規則型 pattern match + AI 驅動告警去重/關聯；修復選擇為宣告式 workflow YAML catalog（trigger→conditions→actions），以 if 條件式邏輯控制執行；文件未明確定義 approval gate，語意近似 fail-open。
  2. k8sgpt-ai/k8sgpt（7,953★，pushed 2026-07-06）— Kubernetes 診斷工具。analyzer 模組化診斷 + 可插拔多 LLM backend；核心無自動修復，純診斷輸出交由人工判斷，天生保守設計。
  3. HolmesGPT/holmesgpt（2,798★，pushed 2026-07-06，CNCF Sandbox，原 robusta-dev/holmesgpt 已更名）— agentic loop（ReAct）+ 40+ 觀測工具集動態蒐證；混合修復模式（可自動執行或僅產出 RCA），透過 GitHub 整合時採 PR-gate（開 PR 待人工審批合併），另有 Slack 通知與 CLI 互動兩個輔助人工介入點。

三者對照出自癒系統設計光譜：k8sgpt（無自動化，最保守）— 本系統現況（有自動修復但無執行前審核）— Keep（隱含 fail-open）— HolmesGPT（PR-gate，執行前審核最完整）。

審查結論

  • Keep 提案：可行性 8/10、穩定性 9/10（純文件新增，無程式邏輯風險）→ 通過，直接落實。
  • HolmesGPT 提案：可行性 6/10（需重新設計 self_heal 執行流程與 config_snapshot 互動）、穩定性 5/10（觸及核心自癒執行路徑，需觀察期驗證延遲影響）→ 未達 7/7 門檻，且涉及 self_heal 核心流程屬 human_review_gates 高風險路徑，升為 risk_level=high，不自動落實，輸出計畫待人工審核。
  • k8sgpt 提案：純觀察性質，不需落實審查，僅記錄於 comparables 供未來參考。

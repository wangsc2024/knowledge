引言

多代理LLM系統的治理研究，自2024年起經歷了一次尚未被充分整理的典範轉移。既有整合性分析多半聚焦於單一面向——組織成熟度三支柱、基礎設施協同設計、或前沿代理評測生態——但鮮少追問：當一個多代理系統的安全規則寫在提示詞裡卻在多輪決策中失去效力時，治理邏輯究竟該安放在架構的哪一層？本文的研究問題是：2025-2026年間爆發的多代理LLM治理文獻，是否存在一個可辨識的架構收斂模式？本文的貢獻有三：其一，系統性比對四類文獻（執行邊界治理層、協定治理縫隙、約束維持機制、評測可測量性），辨識出「政策強制層」此一收斂架構語彙；其二，指出此典範背後未解決的遞迴信任問題；其三，提出企業導入此類架構時的具體選型建議與風險邊界。

文獻回顧

[李飛飛主筆] 第一類文獻聚焦執行邊界的治理層設計。CAMCO 將多代理決策重新表述為受限最佳化問題，以凸投影政策強制引擎、風險加權效用整形與可證明收斂界限的協商協定三件套，在三個企業情境中做到零政策違規、92-97%效用保留[來源：CAMCO, 2026]。這個「數學上可證明」的設計選擇，呼應了我一貫主張的立場：治理不能只是道德勸說，必須有可驗證的數據與界限。Organizational Control Layer 採取類似但更輕量的路線——不修改底層LLM生成器，而在行為執行前攔截提案，在對抗性談判環境中將不安全執行率從88%壓到近零、有效成功率從12%拉到96%[來源：OCL, 2026]。Policy-Driven Runtime Layer 則把治理框架化為系統層問題，主張在框架與推論引擎之間插入第三層「代理運行時層」，暴露 observe/score/predict/act 四個原語，其KV快取管理政策副作用地帶來13-37個百分點的快取命中率提升[來源：Policy-Driven Runtime Layer, 2026]——這提醒我們，治理層若設計得當，甚至可能是效能收益而非純粹開銷。Policies on Paths 進一步把干預單位從「單一決策」拉高到「決策序列」，主張治理責任必須從部署前設計移入運行階段，並直接對齊 EU AI Act 的合規語言[來源：Policies on Paths, 2026]。

第二類文獻處理協定層的治理縫隙。Governance Gaps in Agent Interoperability Protocols 逐一檢視 MCP、A2A、ACP 三個協定，指出 MCP 缺乏授權層級與課責結構的表達能力、A2A 無法充分表達同意框架與爭議解決程序、ACP 難以編碼審計軌跡——三者共同的結論是：技術互通本身不足以構成可信賴的多代理生態[來源：Governance Gaps, 2026]。Institutional AI 把這個縫隙問題從代理層級偏好工程重新框架化為機構層級機制設計，以公開不可變的 governance graph 搭配 Oracle/Controller 運行時解釋器，實驗顯示制度型方案使合謀指標從3.1降至1.8，而純提示詞禁令對照組無顯著改善[來源：Institutional AI, 2026]——這個對照組結果尤其值得注意，它直接證偽了「把安全規則寫進提示詞就夠了」的普遍假設。Multi-Agent Orchestration Protocol 與 LOKA 則是兩條互補的協定層補完路徑：前者把司法轄區規則、Policy Engine 與不可竄改稽核日誌嵌入編排流程[來源：MAOP, 2025]，後者以去中心化識別碼與後量子密碼學把身份、信任、倫理直接嵌入協定層本身[來源：LOKA, 2025]。

第三類文獻是本文論證的技術核心：約束不能只靠靜態規則注入，必須被主動維持。Safe Multi-Agent Behavior Must Be Maintained, Not Merely Asserted 提出「約束漂移」概念——安全規則文字上存在，卻在行動時失去操作力，論文以 AgentLeak 重放實驗證明，僅輸出層過濾使68.8%隱藏洩漏未被處理，轉移層級治理則降至4.6%[來源：Constraint Drift, 2026]。這組數字是全文最關鍵的實證證據：它量化了「規則存在」與「規則生效」之間的落差有多大。AgentSpec 提供了讓約束可執行的具體語法——以觸發事件、條件判斷、強制機制三層 DSL 規範代理行為，在程式碼執行代理上攔下超過90%不安全執行[來源：AgentSpec, 2026]。TraceFix 則把形式驗證帶進這個迴路，用 TLA+ 模型檢查產生反例，再讓LLM分析並提出協定修復建議[來源：TraceFix, 2026]。而在最適化端，Conformal Constrained Policy Optimization、MAMO 與 ArGen 三篇論文顯示，約束強制正從人工調整的懲罰項，轉向用強化學習與 conformal prediction 讓系統自己學會權衡成本與可靠度[來源：CCPO, 2025][來源：MAMO, 2026][來源：ArGen, 2026]。

第四類文獻是尚未解決的短板：評測的可測量性。Measuring AI Agent Autonomy 指出現行自主性評估仰賴昂貴且高風險的運行時觀察，轉而提出以程式碼靜態稽核評分[來源：Measuring Autonomy, 2025]；Beyond Task Success 批評既有評測過度聚焦任務是否成功的二元結果，忽略決策過程與政策遵循的證據鏈[來源：Beyond Task Success, 2026]。AgencyBench 與 Capability Frontier 則從實證角度補強：前者以138項百萬token級任務顯示閉源模型優於開源模型16個百分點，瓶頸不只在模型本身、更在模型與框架的協同配適度[來源：AgencyBench, 2026]；後者指出單模型單次運行評測會低估真實能力達82%[來源：Capability Frontier, 2026]。兩篇論文合起來說明：如果連「能力」都測不準，「合規」的可測量性只會更難。此外，MoE Survey 作為架構背景文獻補充說明，政策強制層必須相容於底層模型持續演進的稀疏化、異質化架構[來源：MoE Survey, 2025]。

研究方法

研究方法遵循 deep-research v3 八相位管線的 Phase 0-5，並依 report_profile=thesis 加驗規格執行。檢索策略採兩階段：Phase 0 以 Semantic Scholar API 為主，先鎖定12篇高相關性種子論文（涵蓋 CAMCO、OCL、Constraint Drift 等核心文獻），再依延伸關鍵詞（policy enforcement layer、agent governance runtime、constraint drift multi-agent、governance gap MCP A2A ACP 等8組）執行 WebSearch 擴大候選池，合計62篇候選。納入排除準則有三：發表時間限定2025-2026年（確保捕捉多代理治理研究爆發期的最新進展）、內容須直接處理治理機制或政策強制架構（排除純理論對齊論文與缺乏技術細節的評論）、排除純行銷性質或無可驗證方法論的產業內容。最終納入22篇獨立來源，19篇A級同行評審或預印本論文、3篇C級產業部落格作為業界實務背景佐證，無任何KB內部筆記入列。三角佐證法方面，本文提出的4項核心主張，每項皆由至少4篇獨立來源交叉驗證後標記「已驗證✅」，並於附錄完整呈現主張與來源的對應矩陣，供讀者逐項覆核。

結果與討論

[李飛飛主筆] 把19篇論文放在一起看，一個清晰的收斂模式浮現：三條表面上出發點不同的技術路徑——執行邊界治理層、協定治理縫隙的補完、約束維持與強化學習式政策強制——正在收斂為同一套架構語彙，本文稱之為「政策強制層」（Policy Enforcement Layer）。這個收斂不是巧合。CAMCO 與 OCL 雖然數學形式不同（前者是凸最佳化，後者是攔截-升級），但共同選擇了「不修改底層LLM生成器，在部署時以獨立中介層介入」的架構位置[來源：CAMCO, 2026][來源：OCL, 2026]；Governance Gaps 發現的協定表達力不足，恰好解釋了為什麼治理邏輯無法留在協定層，只能上移到這個獨立中介層[來源：Governance Gaps, 2026]。而 Constraint Drift 提供的68.8%對4.6%洩漏率對比，則從實證上證明了為什麼「治理邏輯必須是持續運行的狀態維持機制」，而不能是一次性的規則注入[來源：Constraint Drift, 2026]。三條路徑收斂，意味著這不再是某個研究團隊的架構偏好，而是這個問題空間本身的結構性要求——如同 ImageNet 證明「大規模標註數據」是深度學習躍遷的必要條件，這批文獻正在證明「運行時政策強制層」是多代理系統安全的必要條件，而非眾多選項之一。

但收斂本身不等於問題被解決。三篇評測文獻（Measuring Autonomy、Beyond Task Success、AgencyBench）共同指向一個尚未被正視的缺口：我們甚至還沒有一套跨案例可比較的方法，去測量「這個政策強制層本身有沒有在正確地強制」[來源：Beyond Task Success, 2026]。這正是全文的核心關切——一個治理架構若無法被測量，就無法被信任，這與我在 Stanford HAI 一貫主張的立場一致：創新與政策評估必須同步，而非等出了事故才補救。

實踐建議

[Yann LeCun 主筆] 先講結論：如果你正在為企業多代理系統選型治理架構，別去追逐「哪個協定最新」，去看三件事。第一，選擇能以獨立中介層部署、不需要重新訓練或微調底層模型的方案——CAMCO 與 OCL 都做對了這件事[來源：CAMCO, 2026][來源：OCL, 2026]，這才是可規模化的工程選擇，不是每換一個模型就要重跑一次對齊。第二，別滿足於「規則寫在系統提示詞裡」這種假安全感，Constraint Drift 的數據已經說得很清楚：輸出層過濾攔不住68.8%的洩漏[來源：Constraint Drift, 2026]，你需要的是能在決策鏈中段攔截的機制，像 AgentSpec 這種輕量 DSL，毫秒級開銷、90%以上攔截率，這種投報比才值得工程團隊認真考慮[來源：AgentSpec, 2026]。第三，如果你的場景涉及多個異質代理跨組織協作，先假設 MCP、A2A 這些協定本身不會替你處理治理語意——Governance Gaps 已經逐條列出它們表達不了什麼[來源：Governance Gaps, 2026]，治理邏輯要自己在應用層補上，不要等協定標準委員會替你解決，那會等太久。

風險與限制

[Yann LeCun 主筆] 我對這整批文獻最大的保留，是遞迴信任問題沒人真正面對。CAMCO 的政策強制引擎、OCL 的升級處理機制、ArGen 的 policy-as-code——這些系統本身也是軟體，也可能有 bug、可能被對抗性輸入繞過，那麼誰來驗證這個驗證者？文獻裡沒有一篇認真處理這個問題，大多止步於「我們的政策引擎測試通過」，但測試通過不等於形式化正確，這正是我一貫對純經驗主義評測的懷疑立場。第二個限制是產業平台與學術原型的落差：AccuKnox 等產業觀察指出真實攻擊面在代理間交接、RAG 檢索通道、共享上下文儲存[來源：AccuKnox blog, 2026]，但本文回顧的多數學術論文評測環境仍是受控的對抗性談判或程式碼執行沙盒，尚未在生產規模的異質協定環境中驗證。第三，強化學習式政策強制（CCPO、MAMO、ArGen）把治理問題重新表述為獎勵設計問題，這條路徑我一直保持警覺——獎勵設計本身就是個容易出錯、難以審計的環節，把治理外包給一個你自己都說不清楚在優化什麼的獎勵函數，不是解決了信任問題，只是把它藏得更深。這不是要否定這批研究的價值，而是提醒：政策強制層若要從論文走進生產系統，還缺一輪獨立於原作者的紅隊驗證。

原創論點

[李飛飛主筆] 本文論證一個在既有文獻中被低估的觀點：政策強制層典範的真正歷史類比，不是「安全補丁」，而是 TCP/IP 協定棧當年從「盡力而為傳輸」演化出獨立的傳輸控制層——當年網路工程師發現，把可靠性邏輯硬塞進每個應用程式並不可行，必須抽出一層獨立、可重用的協定層來承擔。今天的多代理LLM系統正走上同一條路：Governance Gaps 證明協定層本身裝不下治理語意[來源：Governance Gaps, 2026]，於是治理邏輯被迫上移、獨立成層，這不是設計者的選擇，而是問題空間的結構性壓力使然，如同 TCP 不是應用層程式設計師的偏好，而是可靠傳輸這個問題本身的必然解。

本文進一步主張，這個類比也暴露了目前這批文獻共同的盲點：TCP/IP 的傳輸控制層之所以可信，是因為它有數十年的形式化驗證與大規模生產壓力測試作為後盾；而今天的政策強制層，無論是 CAMCO 的凸最佳化收斂界限，或 AgentSpec 的 DSL 攔截率，驗證規模都還停留在論文等級的三到五個受控情境，遠遠不到 TCP/IP 級別的信任累積[來源：CAMCO, 2026][來源：AgentSpec, 2026]。換句話說，政策強制層目前處於一個危險的中間地帶：架構共識已經形成，但信任基礎設施（可測量性、可稽核性、獨立驗證機制）還沒跟上——這正是 Measuring Autonomy 與 Beyond Task Success 兩篇論文共同指出的缺口[來源：Measuring Autonomy, 2025][來源：Beyond Task Success, 2026]。

我認為，這個落差不會被更多的架構論文自然填補，而需要一個獨立於任何單一政策強制層實作的第三方合規可測量性標準——類似 ImageNet 之於電腦視覺的角色：先有一套所有人都能拿來測試自己系統的共同基準，才能讓「這套政策強制層真的有效」從廠商的自我宣稱，變成可驗證、可比較的工程事實。目前這批文獻裡，沒有一篇扮演這個角色，這正是政策強制層典範走向成熟前，尚待補上的下一塊拼圖。

結論

回到研究問題：2025-2026年間的多代理LLM治理文獻，確實存在一個可辨識的架構收斂模式——本文稱之為政策強制層，其三條技術路徑（執行邊界攔截、約束狀態維持、強化學習式政策強制）雖出發點不同，卻共享「獨立中介層、不修改底層生成器、部署時可插拔」的架構語彙。本文的限制有三：其一，證據來源以2025-2026年預印本為主，同行評審週期尚未完整跑完，部分結論可能隨後續審查修正；其二，三角佐證雖對4項核心主張各以≥4來源驗證，但候選池的檢索仍以英語文獻為主，可能低估非英語地區（如中國、歐盟）的治理框架進展；其三，本文提出的 TCP/IP 類比與獨立基準建議屬於作者原創推論，尚未經產業實證檢驗。後續研究方向有二：一是建立跨政策強制層實作的可比較合規基準，二是針對「驗證者信任遞迴問題」設計形式化證明或獨立紅隊框架，填補本文指出的信任基礎設施缺口。

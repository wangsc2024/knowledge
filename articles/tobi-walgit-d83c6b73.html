偵察提案：tobi/walgit

專案是什麼

walgit 是 Shopify CEO Tobias Lütke 於 2026-08-24 公開的開源 git server，Rust 撰寫、MIT 授權，剛登上 HN 首頁。核心設計：單一 binary 架在 S3/GCS 相容物件儲存之前，無資料庫、無 leader node、無本地狀態，提交採 WAL（write-ahead log）+ CAS（compare-and-swap）語意。提供 smart HTTP v0/v2 git 協定、LFS、瀏覽 Web UI、JSON API/SDK、per-repository push policy 與 webhooks。專案僅公開約 2 天，生產成熟度待查證。

對本系統的借鑑點

  • 時機直接對應：commit dc5edde 剛為 kb-site-publish 補上「git push 連線類失敗退避重試」（know-f push 事故）。walgit 的 WAL+CAS 提交模型示範的是「先寫 WAL、CAS 成功才算數」的冪等保證，而非單純失敗後重打。值得對照 kb-site-publish 目前的退避重試邏輯，檢查是否存在半推送/重複推送的邊界情況（待查證：現有 retry 是否已有等效冪等鍵）。
  • push policy 對應插件路由模式：walgit 的 per-repository push policy + webhooks（誰能推、推哪個分支）可對應「每插件一個進出口」的插件路由模式，作為收斂 kb-site-publish 推送權限的設計參考。
  • 零依賴部署模型作為長期備援選項：單一 binary、無 DB、無 leader 的架構，若未來想降低外部 git host 的連線類故障（CI 帳單停擺期間曾外溢影響本機驗證）對 know-f push 的衝擊，walgit 可作為自架內部 git remote 的候選，但目前成熟度未知，不宜近期依賴。

建議行動

低風險（可先做）：純閱讀 walgit 的 GOAL.md 設計文件，對照 kb-site-publish 現有退避重試程式碼，確認是否已具備冪等保護；不涉及任何程式異動。

需人工決策：是否要實際自架 walgit 作為 kb-site-publish 的 git remote 備援。此舉牽涉基礎設施變更與新增自架服務的維運負擔，且專案僅公開 2 天、尚無生產案例佐證穩定性，建議暫列觀察項目，待其穩定度與社群回饋累積後再評估。

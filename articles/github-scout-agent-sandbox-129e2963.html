GitHub Scout：Agent 安全 / Sandbox（2026-07-03）

專案觀測摘要

  • e2b-dev/E2B（12818★，pushed 2026-07-02）：Firecracker microVM 隔離程式碼執行；顯式 set_timeout()＋kill() 雙軌生命週期管理（軟上限自動到期＋硬性人工終止）。
  • OpenHands/OpenHands（79208★，pushed 2026-07-03，原 All-Hands-AI/OpenHands 已遷移）：Docker 沙箱＋Playwright/BrowserGym 瀏覽器自動化雙層邊界；LLMSecurityAnalyzer 為每次工具呼叫標註 LOW/MEDIUM/HIGH 風險，ConfirmRisky 政策超過門檻即要求人工確認（WAITING_FOR_CONFIRMATION）；但 headless 模式硬編碼 NeverConfirm、local 模式停用容器且無 fallback guard，已有實測破壞性指令直接落地 host 的反例。
  • browser-use/browser-use（102278★，pushed 2026-07-02）：sensitive_data 未設 allowed_domains 即在 Agent 建構期拋出 InsecureSensitiveDataError——fail-closed 硬性閘門，非事後告警。

改進提案

  1. P1／低風險／已落實：config/github-scout-review-policy.yaml → agent_security_tool_use_guardrails.notes 補充「operator_override.default_mode 未明示時應預設視為 deny/review-only」準則（借鑑 browser-use 建構期拒絕）＋ E2B 雙軌 timeout/kill 生命週期模式參考。
  2. P1／高風險／已輸出計畫：docs/plans/github-scout-20260703-pre-bash-guard-risk-escalation.md——為 hooks/pre_bash_guard.py 補上同任務內風險指令累計計數＋升級標記（借鑑 OpenHands LLMSecurityAnalyzer＋ConfirmRisky 情境感知風險升級），先 audit_only 不阻擋；因命中核心攔截層高風險路徑，待人工審核。

審查結論

兩案 feasibility/stability 皆 ≥7；P1 config 案審查 1 輪通過直接落實；高風險案依規則不進入自動落實，直接輸出計畫檔待人工審核（不佔用 5 輪審查額度，符合 human_review_gates.high_risk_paths 規則）。

  • config/github-scout-review-policy.yaml：agent_security_tool_use_guardrails.notes 新增兩則補充說明（已通過 yaml.safe_load 驗證）。

GitHub Scout：MCP 參考實作與策展市集（2026-07-20）

專案觀測摘要

本輪 REST 即時觀測（api.github.com/repos）3 案，呈現 MCP 生態三種不同的 registry_model：

  1. docker/mcp-registry（525★，pushed 2026-07-19）— 建置管線型：PR 提交→自動建置 Docker image→Docker Scout 安全掃描通過才收錄，整合進 Docker Desktop MCP Toolkit。本輪首次跨過本系統 500 星門檻（前次 2026-07-14 複核時未達標未列為正式 project）。
  2. microsoft/mcp（3487★，pushed 2026-07-18）— 單一廠商官方目錄：僅收錄 Microsoft 第一方維護實作，純內部工程審查，無外部提交機制，本系統過去研究未覆蓋的新案例。
  3. modelcontextprotocol/registry（7048★，較 07-14 之 7016 成長 +32，pushed 2026-07-15）— 官方 unopinionated meta-registry：僅託管 namespace+metadata，具體品質判斷委由下游 aggregator（GitHub/Docker/PulseMCP/Microsoft）各自實作。

脈絡補充（未列為正式 project，無 stars 可觀測）：GitHub 官方 MCP Registry（github.com/mcp，2025-09 上線）僅收錄約 40 個嚴選 entries，對比社群 registry 逾 1000 筆自行發布，印證『窄而嚴選』與『寬而自助』兩種策展模式並存。

改進提案

  1. P1（已落實）：將本輪三態 registry_model 對照補入 config/github-scout-review-policy.yaml topic_overrides.mcp_reference_marketplace 主題筆記與 docs/github-scout-agent-comparables.md，供後續研究快速引用。
  2. P2（待人工審核）：docker/mcp-registry 以『建置成功＋安全掃描通過』作收錄閘門，對照本系統 tools/asset_accountability 現行 value_score 純確定性加權（refs0.5+recency0.3+success*0.2），無收錄前安全掃描信號。建議評估是否為新工具/skill 加入四索引前，複用既有 hardcode-detector 或 secret_scan_daily 邏輯做輕量掃描信號。

審查結論

P1 提案：feasibility_score=9、stability_score=9（純文件/config 筆記新增，無行為變更風險），已於本輪落實。

P2 提案：因涉及四索引收錄邏輯與 tools/asset_accountability 判定演算法變更，risk_level=medium-high，需人工評估效益與範圍後方可執行，暫不自動落實。

摘要

[李飛飛主筆] 本文探討一個逐漸被低估的問題：AI 代理能力提升的真正瓶頸，是否已從語言推理轉移至視覺-語言基座架構本身？藉由篩選 47 篇候選文獻並精讀納入 24 篇（A 級來源 13 篇），本文以三角佐證法交叉比對前沿多模態模型的架構文件、GUI 接地基準實測數據，以及中美業界的產品化路徑，建立「架構層—實證層—產業層」三層論證。研究發現：即使最先進的開源視覺代理模型，在專業軟體環境下的接地成功率仍普遍低於 70%；業界已收斂至「原生視覺接地預訓練＋動作標記」的架構共識；而現有代理評估基準多以任務成功率為單一指標，未能區分規劃失敗與接地失敗。本文主張，代理系統工程化的核心風險，不在編排框架的巧妙程度，而在視覺編碼器的解析度處理與動作頭設計，是否被賦予與提示工程同等的一級架構關注。

引言

[李飛飛主筆] 過去兩年，AI 代理（Agent）能力躍升的敘事幾乇經歷了兩次典範轉移：先是從單純語言模型的文字推理，轉向「工具調用＋規劃」的代理框架；如今，隨著 GUI 操作、電腦使用（computer use）、跨應用工作流程成為代理評測的核心場景，敘事重心正在悄悄移向多模態視覺-語言（Vision-Language）架構本身。這個轉移之所以容易被忽略，是因為多數代理編排文獻（如排程、信任校準、知識治理相關研究）預設「感知」已經解決，將注意力全數投向規劃與協調層。然而，若視覺接地（grounding）本身就是主要瓶頸，那麼再精巧的編排設計，也只是在一個不可靠的感知基礎上搭建樓層。

本文的知識缺口在於：現有研究鮮少系統性地將「前沿多模態基座架構演化」「代理編排框架文獻」「代理能力評估方法論」與「GUI 接地基準實證數據」四類文獻並置分析，檢視它們彼此的隱性假設是否一致。研究問題有三：第一，前沿視覺-語言模型的架構設計，是否已將代理能力（如電腦使用）視為原生一級能力？第二，實證基準是否支持「視覺接地是代理失敗主因」此一假設？第三，中美業界的產品化路徑是否呈現架構收斂，抑或仍是各自為政的實驗？本文貢獻在於：以三角佐證法系統性回答上述三問，並指出現行代理評估框架在診斷粒度上的方法論缺口，作為後續研究的具體切入點。

文獻回顧

[李飛飛主筆] 第一組：前沿多模態基座模型架構演化。 Qwen-VL 建立了視覺編碼器與語言解碼器對齊的早期範式，是後續視覺代理能力的架構基礎（[來源：Qwen-VL, 2023]）。Qwen2.5-VL 的官方模型卡進一步說明，其架構已將「電腦使用」與「手機使用」列為原生能力，關鍵工程改動包括重新設計的 ViT 視覺編碼器（2D-RoPE、窗口注意力）與多模態旋轉位置編碼（MRoPE），使模型可直接推理並動態調度工具（[來源：Qwen2.5-VL-72B-Instruct Model Card, 2025]）。DebuggerCafe 的技術部落格補充了官方文件未詳述的工程實作細節，說明窗口注意力如何支援可變輸入解析度（[來源：DebuggerCafe Qwen2.5-VL Architecture, 2025]），這一點對本文論證至關重要：解析度處理並非邊緣工程細節，而是接地精度的直接決定因素。Gemini 2.5 技術報告則從另一個角度佐證同一趨勢——長上下文、多模態與推理能力的組合被明確定位為解鎖「新一代代理工作流程」的關鍵，並以 Gemini Plays Pokémon 為具體案例（[來源：Gemini 2.5, 2025]）。這四篇文獻共同指向：視覺代理能力正被視為基座模型的原生設計目標，而非後續拼接的外掛模組。

第二組：代理編排框架文獻。 Gradientsys 提出以 LLM 為核心的多代理排程器，支援 PDF 解析、網頁搜尋、GUI 控制器等異質代理並行執行，並在 GAIA 基準上優於 MinionS 基線（[來源：Gradientsys, 2025]）；Kandogan 等人提出以「streams」為核心概念的企業複合式 AI 藍圖架構，將既有模型與 API 映射為 agent registry 中的代理（[來源：Orchestrating Agents and Data for Enterprise, 2025]）；Context Kubernetes 則以容器編排類比企業知識治理問題，提出三層代理權限模型並以 TLA+ 模型檢查驗證 460 萬可達狀態零違規（[來源：Context Kubernetes, 2026]）。這三篇論文有一個共同的隱性假設值得注意：它們均聚焦編排層（排程、知識流、權限），但都未直接處理「視覺感知本身是否可靠」這個前置問題——換言之，編排層的形式化驗證再嚴謹，若輸入的視覺接地結果本身有系統性誤差，整體可靠性仍受限。Roumeliotis 等人的研究則是一個例外：他們以蘋果葉病診斷為案例，展示信任校準編排如何提升零樣本視覺分類準確率達 77.94 個百分點，並發現 GPT-4o 校準較佳而 Qwen-2.5-VL 傾向過度自信（[來源：Orchestrator-Agent Trust, 2025]）——這是少數同時觸及編排與視覺接地校準落差的文獻，也是本文三角佐證中被標記「待驗證⚠️」主張的關鍵支持來源之一。

第三組：代理能力評估與預測方法論。 RE-Bench 以 71 次 8 小時人類專家嘗試，對比 AI 代理在真實 ML 研究工程環境的表現，發現代理在短時間預算下優於人類，但人類在長時間預算下反超（[來源：RE-Bench, 2024]），顯示代理表現高度依賴任務的時間結構而非單純架構優劣。Pimpale 等人提出兩階段預測法，預測 2026 年初頂尖代理在 SWE-Bench 上成功率可達 87%（[來源：Forecasting Frontier LM Agent Capabilities, 2025]），但此類預測方法論本身高度依賴既有基準的代表性——若基準未涵蓋 GUI 接地場景，預測便可能系統性高估代理的實際可靠性。Krishnan 的系統性回顧則提出兼顧任務有效性、效率、穩健性與安全性的整體評估框架（[來源：AI Agents: Evolution, Architecture, and Real-World Applications, 2025]），但同樣未特別聚焦視覺接地此一子問題，反映評估文獻整體對「感知層失敗」的關注度不足。

第四組：GUI 接地基準與業界實作。 這是本文論證的實證核心。ScreenSpot-Pro 排行榜顯示，Qwen2.5-VL-7B 僅 27.6%、Qwen2.5-VL-32B 為 39.4%、UI-TARS-72B 為 38.1%，即使頂尖開源模型 GUI-Owl-7B 也僅達 54.9%（[來源：ScreenSpot-Pro Leaderboard, 2026]）；OSWorld-Verified 提供跨模型比較的標準化執行成功率評測環境，是量化代理接地能力的關鍵基礎設施（[來源：OSWorld-Verified, 2025]）。官方實作方面，Anthropic 的 Computer Use 工具讓模型透過螢幕截圖觀察畫面並以滑鼠鍵盤操作環境，且截圖與動作資料留在客戶端而非傳回 Anthropic（[來源：Computer use tool, 2025]），是視覺代理商用化的官方參照；其 Vision 文件則說明影像理解如何整合進 API 呼叫（[來源：Vision, 2025]）。中文技術社群的觀察同樣關鍵：智譜 CogAgent-9B 僅依賴螢幕截圖（不需 HTML 文本表徵）即可執行 GUI 操作，並在多項評測中全面領先（[來源：JadePeng CogAgent-9B blog, 2024]），CogAgent 首次提出 GUI Grounding 預訓練方法，利用螢幕截圖與版面配置對建立介面子區域對應關係（[來源：CSDN CogAgent GUI Grounding, 2024]），而智譜隨後提出 GLM-OS 概念並發布 AutoGLM、GLM-PC 兩款視覺代理產品（[來源：GLM-OS/AutoGLM/GLM-PC, 2024]）。ZenML 分析 1,200 個生產環境 LLM 代理部署案例，歸納出「情境工程優於提示工程」等模式（[來源：LLM Agents in Production, 2024]），Google Cloud 官方工程部落格則強調代理評估應聚焦完整決策軌跡而非僅看最終答案（[來源：A dev's guide to production-ready AI agents, 2026]）。FriendliAI 的產業觀察指出 54% 導入 AI 代理的組織將視覺語言模型用於品質檢測，同時點出 VLM 在邊緣裝置上運算較慢的實務限制（[來源：Automating Industrial Inspection with VLMs, 2026]）。社群層面，Hacker News 社群討論指出開發者實際獲益的方式多為「多個有邊界的工作流程搭配人類監督」而非完全自主（[來源：Developers Digest, 2026]），獨立開發者社群則記錄了以 Qwen2.5-VL 復現類似 OpenAI Operator 電腦使用代理的實作經驗（[來源：Rohan Paul, 2025]）。中文科技媒體亦指出 2026 年企業關注焦點正轉向「世界模型」與「編排調度」並置討論（[來源：TechOrange, 2026]），呼應本文將視覺基座與編排架構並置分析的立場。

研究方法

本研究採三階段檢索與三角佐證法。第一階段候選池建立：以「large language model architecture」「AI agent orchestration」「frontier model capabilities」等中英混合關鍵詞，透過 arXiv、OpenAlex、Semantic Scholar、官方模型卡／文件、工程部落格與社群討論版檢索，取得 47 篇候選文獻（含 title、abstract、year），涵蓋 2023-2026 年區間。第二階段納入排除：依主題相關性（是否涉及視覺-語言架構、代理接地或編排）、時效性、來源可信度分級（A＝同行評審論文/arXiv/官方規範；B＝會議論文/官方技術文件；C＝工程部落格/產業報告/社群討論）三準則篩選，最終納入 24 篇獨立來源（A 級 13 篇、官方文件 3 篇、部落格 7 篇、benchmark 2 篇、社群 3 篇，含中文來源 4 篇）。第三階段三角佐證：針對 5 條核心主張，逐條檢視是否有 ≥3 個獨立來源交叉支持；4 條主張達標並標記「已驗證✅」，1 條主張（編排層優化可獨立於視覺基座提升可靠性）雖有 3 篇來源但論證強度不足，誠實標記「待驗證⚠️」。本研究方法的限制在於：候選池檢索仍受限於公開可索引之文獻與部落格，可能低估未公開的內部工程實踐；ScreenSpot-Pro 為社群維護排行榜，存在提交者自選模型的潛在偏誤。

結果與討論

[李飛飛主筆] 三層論證結構的證據彙整如下。架構層：Qwen2.5-VL、Gemini 2.5 等前沿模型已將視覺代理能力（電腦使用、GUI 操作）內建於基座設計，透過視覺編碼器重設計與多模態位置編碼實現（[來源：Qwen2.5-VL-72B-Instruct Model Card, 2025]、[來源：Gemini 2.5, 2025]）。實證層：ScreenSpot-Pro 與 OSWorld-Verified 顯示，專業軟體環境下的接地成功率普遍低於 70%，即使頂尖開源模型也不例外（[來源：ScreenSpot-Pro Leaderboard, 2026]），且 Roumeliotis 等人的校準實驗證實不同視覺代理模型間存在系統性接地／校準落差（[來源：Orchestrator-Agent Trust, 2025]）。產業層：Anthropic 的 Computer Use 與智譜的 CogAgent／GLM-PC 分屬不同技術文化與市場，卻不約而同走向「原生視覺接地預訓練＋動作標記」的路徑（[來源：Computer use tool, 2025]、[來源：JadePeng CogAgent-9B blog, 2024]），這種跨組織收斂比單一實驗室的技術選擇更具說服力，因為它排除了「個別團隊偏好」的解釋，指向一個結構性的架構共識。

這三層證據與代理編排框架文獻（[來源：Gradientsys, 2025]、[來源：Orchestrating Agents and Data for Enterprise, 2025]、[來源：Context Kubernetes, 2026]）形成值得正視的張力：編排文獻普遍將可靠性問題定位在排程、信任機制或知識治理層面，隱性假設「感知輸入是可信的」。但若接地成功率本身低於 70%，編排層的形式化驗證（如 Context Kubernetes 的 TLA+ 模型檢查）保證的是「權限流轉正確」而非「代理真正理解了螢幕上發生什麼」——這是兩種不同層次的正確性，容易被混為一談。此外，Google Cloud 與 ZenML 的產業觀察都強調應評估完整決策軌跡而非最終答案（[來源：A dev's guide to production-ready AI agents, 2026]、[來源：LLM Agents in Production, 2024]），但目前公開的評估框架（RE-Bench、Forecasting Frontier LM Agent Capabilities）仍以任務成功率為主要指標（[來源：RE-Bench, 2024]、[來源：Forecasting Frontier LM Agent Capabilities, 2025]），未能像 ScreenSpot-Pro 那樣細分「接地失敗」與「規劃失敗」，這正是本文所指出的方法論缺口。

實踐建議

[Yann LeCun 主筆] 基於上述證據，我提出三項具體建議。第一，代理評估基準應強制回報「失敗歸因分解」——區分規劃失敗、接地失敗與執行失敗三類，而不是只給一個籠統的任務成功率；ScreenSpot-Pro 與 OSWorld-Verified 已示範了這種細粒度評測的可行性，應成為新基準的最低標準（[來源：ScreenSpot-Pro Leaderboard, 2026]）。第二，開源社群應優先投入原生視覺接地預訓練資料集與動作標記語料的開放，而非只開放模型權重——CogAgent 的 GUI Grounding 預訓練方法之所以有效，關鍵在於螢幕截圖與版面配置對的資料建構方式，這類資料層面的開放對整個生態系的接地能力提升，價值不亞於單純開源模型參數（[來源：CSDN CogAgent GUI Grounding, 2024]）。第三，企業導入視覺代理時，應先以人類監督的有邊界工作流程起步，而非追求完全自主，這與 Hacker News 社群的實務觀察一致，也是風險可控的部署路徑（[來源：Developers Digest, 2026]）。

風險與限制

[Yann LeCun 主筆] 本文證據存在三項限制，須誠實揭露。第一，三角佐證矩陣中「編排層優化可獨立於視覺基座提升代理可靠性」一條主張，雖有三篇來源支持，但這些論文（Gradientsys、Context Kubernetes、Orchestrating Agents and Data for Enterprise）彼此之間並未直接對比「同一代理系統在視覺基座升級前後、編排層不變」的控制實驗，證據強度僅達「相關性」層次，故標記「待驗證⚠️」，不應被讀者過度延伸為因果結論。第二，ScreenSpot-Pro 為社群維護的公開排行榜，其收錄模型與測試環境的選取標準未必涵蓋所有商用系統，可能存在提交者自選最佳成績的偏誤，本文的「接地成功率普遍低於 70%」結論應理解為在已收錄模型範圍內成立，而非產業全貌的窮盡調查。第三，我必須指出一個更根本的架構疑慮：「原生視覺接地預訓練＋動作標記」這條收斂路徑，本質上仍是在既有的序列預測（next-token prediction）範式上疊加更多視覺 token 與動作 token，而非真正意義上對物理世界建立可預測、可規劃的世界模型（world model）。若接地失敗的根源是模型缺乏對「螢幕狀態如何隨動作演變」的內部世界表徵，那麼單純擴大視覺編碼器解析度或增加動作標記詞彙表，可能只是把同一個問題往後推遲，而非架構性解決——這一點與李飛飛在架構層論證中強調的「原生內建」樂觀判斷存在張力，我在此保留不同意見，留待後續實證研究裁決。

原創論點

[李飛飛主筆] 我提出四項獨立判斷，超越前述文獻的既有結論。

第一，我主張應把「接地失敗歸因」提升為代理評估的科學儀器等級指標，而非附屬診斷資訊。我在 ImageNet 時代學到的教訓是：真正推動領域躍遷的往往不是更聰明的演算法，而是更嚴謹的數據與評測基礎設施——ImageNet 讓「識別準確率」成為可比較、可累積的科學度量衡，才使深度學習的進展有了共同語言。今天的代理評估同樣需要這種基礎設施等級的度量衡：把「規劃失敗 vs. 接地失敗 vs. 執行失敗」的分解度量，做成像 ImageNet Top-1/Top-5 一樣被所有實驗室共同採用的標準欄位，而不是各家基準各自為政的附加說明。

第二，我認為「視覺基座即代理基座」這個轉向具有被低估的人本意涵。誰的螢幕介面容易被準確接地，誰的就容易？現有 GUI 接地基準（ScreenSpot-Pro、OSWorld）多以英語作業系統與主流商用軟體為測試環境，中文介面（如 CogAgent、GLM-PC 鎖定的中文辦公場景）與非主流排版習慣的接地表現，在公開文獻中幾乎沒有獨立量化數據——這意味著我們可能正在用一套對特定語言與介面慣例友善的基準，去衡量一個號稱普適的技術能力，這正是「誰被排除在數據外」這個問題在視覺代理領域的新變體，值得後續研究補上這塊空白。

第三，關於 Yann LeCun 在「風險與限制」中提出的世界模型質疑，我認為兩人的立場並非真正矛盾，而是分屬「工程可用性」與「科學完備性」兩種不同的評價座標。從工程可用性角度，原生視覺接地預訓練確實在短期內帶來可量測的能力提升（如 CogAgent 在多項評測全面領先），這是值得肯定的階段性進展；但從科學完備性角度，若缺乏對動作如何改變螢幕狀態的內部世界表徵，這條路徑的能力提升曲線很可能在達到某個複雜度門檻後趨緩——這與 RE-Bench 顯示「代理在長時間預算任務上不如人類」的現象方向一致，暗示當前架構在長程規劃與狀態追蹤上確有其結構性限制。因此我主張，這不是二選一的路線之爭，而是短期工程投資（擴大原生接地預訓練規模）與中長期研究投資（探索世界模型式的狀態表徵）應該並行，而非互斥。

第四，我判斷現行「代理編排框架」文獻對視覺接地問題的忽視，並非疏漏，而是反映了一種學科分工的路徑依賴——編排研究多源自分散式系統與多智能體協調的傳統，其方法論工具（形式化驗證、排程理論）天生適合處理「協調正確性」而非「感知準確性」問題。這個判斷的實踐意涵是：未來想真正解決代理可靠性問題的團隊，需要主動打破這種學科邊界，讓做視覺-語言基座的團隊與做編排系統的團隊建立更緊密的聯合評測機制，而不是各自優化各自熟悉的那一層。

結論

本文以三角佐證法系統性檢視「視覺基座即代理基座」這一命題，回答了三個研究問題：前沿多模態模型確已將視覺代理能力原生內建於基座架構；GUI 接地基準的實證數據支持「視覺接地是代理失敗主因」的假設，且此一格局在中美不同技術文化中同步出現；而現有代理評估框架在診斷粒度上存在明確缺口，尚未系統性區分規劃失敗與接地失敗。本文的限制在於：檢索範圍受限於公開可索引文獻，「編排層優化獨立於視覺基座」一條主張證據強度僅達相關性層次而非因果層次，且 ScreenSpot-Pro 等排行榜可能存在提交者自選偏誤。後續研究方向包括：建立跨語言、跨介面慣例的接地基準以檢驗人本評估缺口；設計能同時分解規劃與接地失敗的複合式評測協定；以及推動視覺基座工程團隊與代理編排研究社群之間更緊密的聯合驗證機制，讓「架構層—實證層—產業層」三層證據能在下一輪模型迭代中持續交叉驗證，而非各說各話。

研究問題與範疇

[李飛飛主筆] 過去幾年，大型語言模型架構的討論主軸多半是「規模定律」（scaling law）：更多參數、更多資料、更多算力，指標持續上升。這延續了我在 ImageNet 時代體會到的直覺——資料與基準能推動整個領域躍遷。但 2026 年的文獻出現一個值得正視的轉折：當我們把鏡頭從「訓練時能做什麼」轉向「部署後實際承受什麼」，會發現真正卡住工程團隊的往往不是模型不夠聰明，而是自回歸 Decode 階段的記憶體存取與互連頻寬這個物理現實［來源：Challenges and Research Directions for LLM Inference Hardware, 2026］。這是一個值得認真對待的訊號：如果架構選擇的真正驅動力已經下沉到硬體層的物理約束，那麼「哪一種架構更好」這個問題，就不能只用困惑度（perplexity）或單一基準分數來回答，而必須把記憶體頻寬預算當成第一級的評測維度。

本文範疇鎖定三個交叉子問題：(1) Decode 階段瓶頸的物理性質為何——是算力不足，還是記憶體與互連延遲；(2) 架構層與系統層如何回應這個瓶頸——KV Cache 壓縮與 SSM/線性注意力混合架構是否為同一因應邏輯的兩個層次；(3) 這個回應方案在長文本、多查詢聯合檢索等真實工作負載上的極限何在。研究對象刻意排除本任務歷史清單中已覆蓋的 20 個主題（含多代理編排、前沿能力評估失準、世界模型/JEPA、指令微調資料策展等），聚焦於一般（單模型、非代理編排場景）大型語言模型核心架構層與其推論硬體物理基礎之交集——這是既有選題尚未觸及、但 2026 年文獻密度明顯上升的縫隙。

過程中曾比較三個候選框架：其一是「次二次方注意力替代架構的效能鴻溝」（偏純架構理論）；其二是「KV Cache 壓縮技術地圖」（偏單一技術面向）；其三是本文採用的「記憶體頻寬牆驅動架構重構」（將硬體約束、壓縮技術與架構轉型三者放進同一因果鏈）。選擇第三個框架，是因為前兩者各自成理但都只解釋了現象的一半，唯有把物理約束當成因、把壓縮與架構轉型當成果，才能解釋為何 2026 年兩條技術路線會同時加速發展。

文獻探討

[李飛飛主筆] 三條文獻脈絡值得並陳檢視。

第一條是推論硬體物理限制脈絡。《Challenges and Research Directions for Large Language Model Inference Hardware》明確指出，Transformer 的自迴歸 Decode 階段運算密度遠低於訓練或 Prefill 階段，主要瓶頸是「memory and interconnect rather than compute」，並提出 High Bandwidth Flash、Processing-Near-Memory、3D 記憶體堆疊、低延遲互連四項研究方向作為物理層解方［來源：Challenges and Research Directions for LLM Inference Hardware, 2026］。這個結論被至少兩篇聚焦推論系統設計的論文獨立佐證：《Prefill vs. Decode Bottlenecks》從 SRAM 頻率與記憶體頻寬上限的角度，具體拆解 Prefill（運算密集）與 Decode（記憶體密集）的資源特性差異［來源：Prefill vs. Decode Bottlenecks, 2025］；《Nexus》則從系統工程角度提出在單一 GPU 內主動分離 Prefill 與 Decode 資源配置，正是因為兩階段的瓶頸性質根本不同［來源：Nexus, 2025］。另有研究進一步提出將 Decode 階段的注意力計算卸載至 CPU，理由同樣是「Decode 階段的注意力運算是記憶體頻寬受限、算術強度低」［來源：Parallel CPU-GPU Execution for LLM Inference, 2025］。四篇獨立文獻在「Decode 是記憶體/互連瓶頸而非算力瓶頸」這一點上高度收斂。

第二條是次二次方/狀態空間架構脈絡。《On Subquadratic Architectures: From Applications to Principles》系統性回顧了以遞迴、狀態空間與線性注意力機制為基礎的次二次方替代方案，並指出 Samba、Nemotron Nano、Kimi Linear、Olmo Hybrid 等 2026 年混合基礎模型已用次二次方序列運算子取代大部分注意力層［來源：On Subquadratic Architectures, 2026］。《Mamba-3》延續狀態空間模型路線，強調其相較線性注意力能維持常數記憶體與線性運算成本的特性［來源：Mamba-3, 2026］；《InfoMamba》則進一步提出「無注意力」的混合 Mamba-Transformer 設計［來源：InfoMamba, 2026］。這條脈絡的關鍵限制在《Mamba-360》這篇較早的綜述中已被指出：純次二次方模型在長文本序列上與注意力機制存在困惑度落差［來源：Mamba-360, 2024］；《Overcoming Long-Context Limitations of State-Space Models》具體將這個落差定位在「多查詢聯合檢索」（multi-query joint recall）任務，並提出以情境相依稀疏注意力（Context-Dependent Sparse Attention）補強 SSM［來源：Overcoming Long-Context Limitations of SSMs, 2025］；《Understanding and Enhancing Mamba-Transformer Hybrids》則專門研究如何強化混合架構的記憶回想（memory recall）能力［來源：Understanding and Enhancing Mamba-Transformer Hybrids, 2025］。兩篇綜述——《The End of Transformers?》與《Speed Always Wins》——則從更宏觀角度將這整條技術路線定位為「後 Transformer 效率典範轉移」的一部分［來源：The End of Transformers?, 2025；Speed Always Wins, 2025］。

第三條是KV Cache 壓縮脈絡，這是目前對既有 Transformer 架構最直接、風險最低的緩解路徑。《KV Cache Compression for Inference Efficiency in LLMs: A Review》將既有技術系統化為五大方向：cache eviction、cache compression、hybrid memory solutions、novel attention mechanisms 與 combination strategies［來源：KV Cache Compression for Inference Efficiency, 2025］；《KV Cache Optimization Strategies for Scalable and Efficient LLM Inference》做了同等系統性的回顧，並比較各技術在記憶體節省、吞吐量與模型準確度上的部署權衡［來源：KV Cache Optimization Strategies, 2026］。在具體工程實作上，《Reimagining Memory Access for LLM Inference》提出壓縮感知記憶體控制器設計，利用 KV Cache 的跨 token 相關性搭配標準無損壓縮器，將 KV Cache 減少最多 46.9% 而不損及模型準確度［來源：Reimagining Memory Access for LLM Inference, 2025］；《Oaken》則提出線上-離線混合 KV Cache 量化方案搭配客製硬體模組［來源：Oaken, 2025］。這條脈絡與第二條脈絡有清楚的分工關係：KV Cache 壓縮是「在既有 Transformer 架構內」緩解記憶體壓力，而 SSM/混合架構是「改變架構本身」以從根本減少 KV Cache 佔用——兩者是同一物理約束下的兩種因應層次，而非互斥選項。三條脈絡分開看各自成理，但少有文獻把它們放進同一個因果鏈——這正是本文核心論證要處理的縫隙。

核心論證

[Yann LeCun 主筆] 我見證過 CNN 到 Transformer、再到現在這波次二次方架構的轉移，這次的模式其實似曾相識：每一次架構典範轉移，表面上看是「新想法比較聰明」，實際上都是某個具體的 inductive bias 選擇，撞上了某個具體的物理或資料限制。這次的物理限制講得很清楚：Decode 階段是 memory-bound，瓶頸是頻寬與互連，不是算力［來源：Challenges and Research Directions for LLM Inference Hardware, 2026］。而 KV Cache 隨上下文長度線性膨脹，正是把這個物理限制直接轉譯成工程成本的機制——這不是一個可以靠「再多等一代硬體」解決的暫時問題，而是注意力機制本身的 inductive bias（每個 token 都要跟所有歷史 token 互動並快取其 key/value）與記憶體頻寬這個稀缺資源之間的結構性衝突。

正因如此，我認為把 KV Cache 壓縮和 SSM/混合架構這兩條技術路線分開討論，會錯過它們真正共享的邏輯。KV Cache 壓縮（量化、驅逐、壓縮感知記憶體控制器）本質上是在不改變注意力這個 inductive bias 的前提下，緩解它帶來的記憶體代價［來源：KV Cache Compression for Inference Efficiency, 2025；Reimagining Memory Access for LLM Inference, 2025］——這是戰術層的止血。而 SSM 與線性注意力混合架構則是直接改變 inductive bias 本身：用具有常數記憶體、線性運算成本的狀態空間運算子，取代大部分需要無限增長 KV Cache 的注意力層［來源：Mamba-3, 2026；On Subquadratic Architectures, 2026］——這是戰略層的架構手術。兩者不是競爭關係，而是同一個問題在不同時間尺度上的解法：短期用壓縮技術爭取喘息空間，長期用架構轉型從根本降低對記憶體頻寬的需求。

但我要在這裡明確反駁一種過度簡化的敘事：「SSM/線性注意力終將完全取代 Transformer」。證據不支持這個強版本。《Mamba-360》早就指出純次二次方模型在長文本上有困惑度落差［來源：Mamba-360, 2024］，而《Overcoming Long-Context Limitations of State-Space Models》把這個落差精確定位在多查詢聯合檢索任務上，並且解法是「加回」情境相依的稀疏注意力，而不是讓 SSM 更純粹［來源：Overcoming Long-Context Limitations of SSMs, 2025］。《Understanding and Enhancing Mamba-Transformer Hybrids》同樣是在研究如何強化混合架構的記憶回想能力，而非追求全面替代［來源：Understanding and Enhancing Mamba-Transformer Hybrids, 2025］。這些證據指向同一個結論：檢索（recall）這個能力，某種程度上就是需要對每個歷史 token 保有可定址、可精確比對的表示——這正是注意力機制的 inductive bias 擅長的事，而 SSM 的固定大小隱狀態在設計上就是要壓縮歷史資訊，兩者在「檢索精度」與「記憶體效率」之間存在根本性的權衡（trade-off），不是工程調校能完全消除的。

這也是為什麼 2026 年中業界收斂到的實際做法，是像 Samba、Nemotron Nano、Kimi Linear 這類混合架構——用少量全注意力層搭配大量次二次方層［來源：On Subquadratic Architectures, 2026］，而非任何一種純架構。有部落格報導引用 Jamba 論文的具體數字：以 7:1 的 Mamba 對注意力層比例，可消除約 87.5% 的 KV Cache 記憶體需求，使 256K token 上下文只需約 4GB KV Cache（bf16、130 億啟用參數規模）［來源：Mamba-Transformer Hybrids, 2026（部落格轉述，需核對原始 Jamba 論文）］——這個數字本身需要謹慎看待其來源，但它呈現的方向與《On Subquadratic Architectures》的系統性回顧一致：混合比例本身變成一個需要與硬體記憶體階層共同設計的架構超參數，而不是事後才調的效能旋鈕。我的立場很直接：沒有把 Decode 階段的記憶體頻寬約束當成一等公民的架構設計，長期都會撞上同一道牆——這不是模型不夠聰明的問題，是架構的 inductive bias 沒有對齊物理現實的問題。

一家之言

[Yann LeCun 主筆] 如果要我用一句話總結：注意力機制從來不是唯一正確的答案，它是 2017 年那個時間點下，對「如何讓模型在訓練時平行處理序列」這個問題的一個具體工程解——而工程解是會過時的，尤其是當部署場景（長上下文、高並發推論、邊緣裝置）的限制條件早已不同於當年的訓練場景。這幾年業界對「規模夠大就能解決一切」的迷戀，某種程度上跟這次的教訓是同一種懶惰的樂觀主義：只要參數夠多、資料夠多，架構本身的選擇不重要。但記憶體頻寬牆這個物理現實很誠實地打臉了這種想法——它不管你的模型有多聰明，KV Cache 該佔多少記憶體、該花多少頻寬搬運，是由架構的 inductive bias 決定的，不是由參數量決定的。

我認為 2026 年這波次二次方/混合架構的興起，真正有意義的地方不是「找到了比注意力更聰明的機制」，而是業界終於願意把架構選擇當成一個要跟硬體記憶體階層共同最佳化的系統工程問題，而不是一個獨立於部署環境的抽象數學選擇。Jamba 式的 7:1 混合比例、《On Subquadratic Architectures》回顧的多個 2026 年混合基礎模型，本質上都是在做同一件事：把「這一層要不要有全域可定址的 KV Cache」變成一個逐層可調的架構決策，而不是預設每一層都要有。這跟我在 CNN 時代學到的教訓一脈相承——平移不變性（translation invariance）是一個具體寫進權重共享機制裡的 inductive bias，不是靠更大的全連接網路「學出來」的；這次的教訓是，「哪些 token 需要被精確記住、哪些只需要被壓縮摘要」也是一個可以明確寫進架構結構裡的設計選擇，不必然要交給規模去暗中解決。

我對接下來 12 到 18 個月的預測是：架構搜尋會出現一個明確的分野。一派會繼續把「多加幾層注意力、多堆一點參數」當成解決長文本、高並發部署問題的預設答案，這條路徑會持續有效，但邊際成本會越來越明顯地反映在記憶體帳單上。另一派會把「每一層要放注意力還是狀態空間運算子」「KV Cache 該在哪一層被驅逐或壓縮」當成與目標硬體的記憶體頻寬和容量共同求解的架構搜尋問題——這條路徑短期工程複雜度更高，需要更成熟的訓練與服務工具鏈（目前這方面的工具成熟度確實還落後純 Transformer 生態），但長期是唯一能讓效能-成本前沿持續往外推的路徑。我不認為這是在否定 Transformer 或注意力機制的價值——檢索能力的證據很清楚地顯示注意力仍是不可或缺的成分——但我確實認為，任何假裝「架構選擇與硬體無關、規模可以解決一切記憶體問題」的敘事，都是在迴避一個已經被多篇獨立文獻證實的物理現實。這不是悲觀，這是工程紀律：認清哪些是可以被規模掩蓋的軟性限制，哪些是必須被架構設計正面處理的硬性限制。

實踐建議

[李飛飛主筆] 從人本與可落地的角度，我認為三條建議值得工程團隊優先考慮：

第一，把 KV Cache 記憶體頻寬預算當成架構設計的一級輸入，而非部署後才調校的效能旋鈕。《Prefill vs. Decode Bottlenecks》與《Challenges and Research Directions for LLM Inference Hardware》的證據顯示，Decode 階段的記憶體與互連特性和訓練/Prefill 階段截然不同［來源：Prefill vs. Decode Bottlenecks, 2025；Challenges and Research Directions for LLM Inference Hardware, 2026］，沿用「先把模型訓好、再想辦法讓它跑快」的舊思維，會系統性低估長上下文、高並發場景下的實際部署成本。建議團隊在架構草圖階段就估算目標上下文長度與並發量對應的 KV Cache 頻寬需求，並將「每層是否需要全域注意力」納入架構搜尋的評分函數，而非只優化困惑度或下游任務準確率。

第二，評測體系需要把「架構效率」與「模型能力」分開計分。《KV Cache Compression for Inference Efficiency》與《On Subquadratic Architectures》的系統性回顧顯示，效率技術的選型高度依賴任務類型與部署場景［來源：KV Cache Compression for Inference Efficiency, 2025；On Subquadratic Architectures, 2026］——如果評測只看端到端任務分數，會把「模型不夠聰明」和「架構效率不佳」混為一談。這正是我在 ImageNet 時期學到的教訓的另一個版本：沒有好的診斷性基準，你優化的永遠是錯的變數。建議團隊在報告模型能力時，同步揭露每單位品質所需的 KV Cache 記憶體佔用（如 MB/token/layer）與每秒 token 吞吐量，讓效率與能力成為可以獨立比較、獨立追蹤進展的兩條曲線。

第三，效率提升的人本意涵必須提前納入架構決策，而非留給事後的碳足跡報告。記憶體頻寬與運算效率的提升，直接關係到模型部署的成本門檻——KV Cache 佔用減少 46.9%［來源：Reimagining Memory Access for LLM Inference, 2025］或混合架構的記憶體節省，意味著同等能力的模型可以在更便宜的硬體上服務更多使用者，這對資源受限的機構、開發中地區的研究團隊、以及需要在地端部署的應用場景，是實質的可及性差異，而不只是雲端供應商的成本優化。我認為技術團隊在評估架構選型時，應該明確將「這個架構選擇是否讓能力更廣泛可及」列為與效能、準確率同等重要的決策準則，而不是等到部署規模夠大、能耗問題被媒體關注後才回頭補救。

風險與限制

[Yann LeCun 主筆] 本文論證有四個明確限制，必須誠實列出。

第一，Jamba 式混合比例的具體數字（7:1、87.5% KV Cache 減少、4GB@256K）引自部落格對原始論文的轉述，本次調研未直接查證 Jamba 原始論文全文與其實驗設定細節［來源：Mamba-Transformer Hybrids, 2026］。這個數字用於說明「混合架構能大幅降低 KV Cache 佔用」這個方向性趨勢是合理的，但具體百分比是否能跨任務、跨規模泛化，讀者應以原始論文查證為準，不應直接引用本文轉述的數字做決策依據。

第二，次二次方架構在長文本多查詢聯合檢索上的落差是活躍研究問題，尚未有壓倒性解方。《Overcoming Long-Context Limitations of State-Space Models》提出的情境相依稀疏注意力［來源：Overcoming Long-Context Limitations of SSMs, 2025］與《Understanding and Enhancing Mamba-Transformer Hybrids》的強化方案［來源：Understanding and Enhancing Mamba-Transformer Hybrids, 2025］都是緩解而非消除這個落差；稀疏注意力本身也帶回部分二次方成本的疑慮，效率增益能否長期維持仍需持續觀察，本文不宣稱這個問題已被解決。

第三，記憶體頻寬瓶頸本身可能被新記憶體技術緩解，屆時本文「架構典範轉移」的急迫性判斷可能需要修正。《Challenges and Research Directions for Large Language Model Inference Hardware》提出的 High Bandwidth Flash、Processing-Near-Memory、3D 記憶體堆疊等方向仍屬研究階段，尚未量產普及［來源：Challenges and Research Directions for LLM Inference Hardware, 2026］；若這些硬體層解方在未來 1-2 年內大幅舒緩記憶體頻寬壓力，架構層轉向次二次方/混合設計的迫切性可能下降，本文應被視為 2026 年中特定技術棧條件下的條件性結論，而非永久架構定律。

第四，本次調研以 arXiv 摘要與 WebSearch 節錄為主，未逐篇通讀全文實驗設定、消融研究與訓練細節，KV Cache 減少百分比、困惑度落差幅度等量化數字如與原始論文有出入，應以原文為準；不同論文的評測基準與任務分佈也不完全一致，本文將其並陳是為了呈現「趨勢方向一致」，而非宣稱可直接數值疊加比較。

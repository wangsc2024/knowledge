深度研究洞察簡報：Instinct 學習引擎導入（digest-memory 行為模式演化）mechanism 階段——候選聚類與 confidence 演化函式設計

日期：2026-07-26　任務：insight_briefing　系列：instinct-behavior-learning-ddp-digest-memory（synthesis→mechanism）

摘要

依 context/research-advancement-queue.json 與 07-25 synthesis 定稿，本輪聚焦 mechanism：在 report-only 前提下，為 23 組 (agent, signal_tag) 候選設計確定性聚類與 confidence 單調更新草案，並對照 2026 年 CEB（Critic Experience Bank）、CLAG 聚類記憶與 COSE 信心加權自演化文獻。萃取 6 項洞見、套用 3 組思考透鏡；KB 語義快取 7 日 lookup/store=0、fastembed 不可用（degraded）。不寫入 state/behavior-instincts.json。

---

核心洞見

1. 二階段聚類：先硬鍵合併，再 P1 fingerprint 子分裂

synthesis 已鎖定候選鍵 (agent, signal_tag) 與可選 fingerprint（僅 P1 五組）。mechanism 建議：

| 階段 | 輸入 | 輸出 | 演算法 |

|------|------|------|--------|

| L0 | 23 組候選 JSON | 18–20 組 | 同 agent+signal_tag 合併 stats（sum count、union distinct_days） |

| L1 | P1 五組 | ≤3 根因簇 | sha256(tool\|path_prefix)[:12] 相等則併入同簇；否則維持二維鍵 |

此設計呼應 CLAG（ACL 2026 Findings）：聚類是寫入時的輕量結構化，非離線全量 k-means，避免 DDP 管線引入 LLM 聚類成本。

2. confidence 演化：證據階梯 + 時間衰減（0.3–0.9 夾逼）

對照 schema v1.0 與 fabrication_guard P3（<0.5 標 speculative）：


base = 0.35
+ 0.05 * min(evidence_count, 6)           # 次數飽和於 +0.30
+ 0.05 * min(distinct_days_observed, 4)   # 跨日穩定 +0.20
- 0.10 if last_observed older than 14d    # 衰減（可選 observe 模式）
clamp to [0.3, 0.9]

晉升至 instincts 層仍須 review_status=approved；confidence 僅排序候選優先級，不自動 enforce。

3. CEB 的「事後偽標籤」可映射到 io-guard 事件，但不複製訓練環

arXiv:2607.12397 以 hindsight 軌跡標 productive/unproductive 步驟並存入 experience bank，推論時改善 ECE 最高 54%。DDP 對照：

  • 可借鑑：同一 (agent, signal_tag) 重現時，檢索過往 stats 作為 critic 上下文（report-only 寫入 briefing／candidates JSON）。
  • 不可直接搬：CEB 需完整 trajectory；structured log 僅有 harness 標籤，無逐步 ground truth → 僅能做弱監督（count/distinct_days），不得宣稱校準達 CEB 水準。

4. COSE 信心加權：用於 backlog 排序，不用於自動寫 state

arXiv:2605.28010 以 Validator/Judge 輸出熵作 sample weight。DDP 映射：候選 priority（P0–P3）× 上式 confidence 作 arch_evolution 佇列分數；DDP_BEHAVIOR_INSTINCTS≠enforce 時不觸發任何寫入。

5. digest-memory 與 instinct 層的資料流分界不變

context/digest-memory.json 續記 topics／streak；mechanism 產出僅建議更新 context/behavior-instinct-candidates.json（git 審計）與本簡報。向量 KB 不重複嵌入候選計數（KB 檢索已命中 07-25 synthesis 筆記，見 hybrid topK=5）。

6. P0 歸因修復仍是聚類有效性的前置（27.3% agent 缺失）

optimization／synthesis 已量化：白名單信號中 38% 與 MISSING agent 綁定。mechanism 聚類若不含 hard_gates.attribution，會產生不可撤銷的幽靈簇——應先合併 post_tool_logger TASK_KEY fallback 提案再跑 L1 fingerprint。

---

建議行動

  1. arch_evolution：審議 mechanism 草案後，以工具腳本（非 LLM）從 structured logs 重算 23→N 簇，輸出 context/behavior-instinct-candidates.json v1。
  2. 實作 confidence 函式於 tools/（若核准）：純函式 + 單元測試，DI 固定 now；預設 observe 模式。
  3. 月度對照：P1 fingerprint 試行 30 日後複查能否收斂至 ≤3 根因（synthesis 成功標準）。

透鏡選擇

框架化建議

  • Altman 視角：把 behavior-instincts 當 API 產品——先 observe 收集真實 (agent, tag) 分佈，再談 enforce；算力（掃 log）便宜才 meter。
  • Jensen 視角：聚類 = 記憶子工廠；L0/L1 兩段式對應晶片封裝——先在確定性層收斂，再考慮 LLM 語意路由（CLAG 式 agent-driven clustering 留作 v2）。
  • Taleb 視角：寫入 state/behavior-instincts.json 是 skin-in-the-game 事件——錯誤模式會在每次 auto-task 放大；預設必須是 antifragile 預設拒絕（report-only + 人工 approved），禁止「平衡觀點」式自動晉升。

反模式檢查

  • 不用「權衡利弊」掩飾：要麼維持 observe，要麼在 attribution 修復後 enforce——中間全量寫 state 是 fragile 的中間地帶（distill-taleb 反模式 #5/#7）。
  • 不引用未驗證的「研究表明」聚合 confidence；僅引用 CEB/CLAG 論文 具體指標（如 ECE −54%）並標 DDP 資料缺口。

透鏡盲區自陳

  • Altman／Jensen 透鏡偏 規模與平台，對 單人 Windows 排程管線的 log 體量可能過度設計 LLM 聚類。
  • Taleb 透鏡對 已存在的 fabrication_guards 重複警告，可能低估 DDP 既有 P1–P4 治理成熟度。
  • 三透鏡均未覆蓋 佛教／內容類 task 與 harness 標籤分佈偏斜——mechanism 統計需分 task_family 切片（留待下輪）。

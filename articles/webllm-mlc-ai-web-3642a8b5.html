偵察提案：WebLLM（mlc-ai/web-llm）

專案是什麼

純瀏覽器內運行的高效能 LLM 推論引擎：靠 WebGPU 加速、WebAssembly 補 CPU 運算，完全不需伺服器；架構分兩層——暴露給網頁的輕量前端引擎與在 worker thread 實際算的後端引擎，對外提供 OpenAI 相容 API。已有 arXiv 論文佐證效能達原生約 80%，屬成熟開源專案。

對本系統的借鑑點

已讀取 examples/plugins/llm-responses/api.mjs 核實：目前唯一的重試層（RESPONSES_RETRY_DELAYS_MS）只包住 HTTP 呼叫，5xx／逾時／網路瞬斷重試耗盡後（api.mjs:453-454）直接 throw，沒有任何非網路的降級路徑。再讀 llm-router/index.mjs 核實其設計鐵律（第 2 行註解）：「明確指定 provider 就不 fallback，避免悄悄切到另一個要付費端點」。WebLLM「零伺服器、零網路依賴」正好對上這個缺口——可評估將它包成 llm-router 的一個顯式 provider（如 webllm.local），供 quality-gate 自評或離線開發測試使用，且須維持「顯式選才用、不進自動 fallback 鏈」的既有原則，不動搖既有的付費端點保護邏輯。

建議行動

低風險：先查證 @mlc-ai/web-llm 這個 npm 套件能否脫離瀏覽器、在 Node headless WebGPU（如 Dawn binding）環境執行——此點目前只在瀏覽器場景被驗證過，待查證，不落地任何程式碼。

需人工決策：若查證通過，是否要在 AGENTS.md 既有六級 sideEffects 分類外新增「零網路」層級，這是治理規則的擴充，非單純程式改動，須人工核可。

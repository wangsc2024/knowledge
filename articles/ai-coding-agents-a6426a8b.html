AI Coding Agents 於單元測試生成之現狀：準確率、覆蓋率與維護成本的三角權衡

摘要

AI coding agents 生成程式碼的速度已明顯超前測試撰寫能力，形成「測試缺口」[S2][S6]。多個獨立 benchmark（TestGenEval、SWT-Bench、Artificial Analysis Coding Agent Index）顯示：在真實世界複雜函式上，AI 生成測試的首次正確率僅一成出頭，覆蓋率也普遍偏低；但透過執行回饋（execution-guided）與自我修復機制，表現可大幅提升。準確率、覆蓋率與維護成本三者之間存在明顯權衡，且不同 benchmark 因任務定義差異而給出落差極大的「準確率」數字，需謹慎解讀。

背景與現況

隨著 AI coding agent 普及，程式碼產出量爆炸性成長——業界估計 2025 年已有 41% 的新程式碼由 AI 生成或輔助完成，且預期於 2026 年底前跨越 50% 門檻[S2]；另一份 2026 年的產業分析亦指出「超過 40% 的新程式碼由 AI coding agent 撰寫或大量協助」[S6]。然而測試撰寫的自動化程度並未同步跟上,「程式碼生成已超越測試撰寫 3–5 倍」[S2]，形成明顯的品質風險缺口——SmartBear 於 2026 年 5 月的調查顯示，70% 的工程領導者認為 AI 正在降低應用程式品質[S2]。

為量化這個缺口，學界與業界近年推出多個專門針對「測試生成」的 benchmark，而非沿用泛用的程式碼生成評測。其中 TestGenEval 以 SWEBench 為基礎，收錄 11 個維護良好的 Python 專案、1,210 組程式碼與測試檔配對、共 68,647 個測試案例，涵蓋「從零撰寫測試套件」與「補強既有測試套件覆蓋率」兩種情境[S1]。另一個方向是 SWT-Bench，聚焦於「重現回報的 issue」這一更窄的任務：生成的測試須在原始程式碼上失敗、在修復後的程式碼上通過[S4]。此外，Artificial Analysis 建立了涵蓋 DeepSWE、Terminal-Bench v2.1、SWE-Atlas-QnA 三項 benchmark 的 Coding Agent Index，同時追蹤 agent 的成本、token 用量與執行時間，將測試生成置於更廣的「coding agent 整體效能」框架下評估[S3]。

在使用者感受層面，Sonar 於 2026 年的《State of Code》調查顯示 59% 的開發者認為 AI 測試生成有效，但 Stack Overflow 2025 年的調查同時顯示僅 29% 的開發者信任 AI 工具的準確性[S2]——這個「有效但不被信任」的落差，正是本報告要深入剖析的核心張力。

機制與技術分析

覆蓋率上限偏低，且模型間差距不大。 TestGenEval 對 7B 至 405B 參數規模的多個主流模型進行評測，結果顯示即便是表現最佳的 GPT-4o，平均程式碼覆蓋率也僅達到 35.2%[S1]。研究團隊將此歸因於模型「難以推理程式執行過程」，在處理複雜執行路徑時經常產生斷言（assertion）錯誤[S1]。這指出一個關鍵機制瓶頸：測試生成不同於一般程式碼補全，它要求模型在缺乏實際執行結果的情況下，準確預測程式在特定輸入下的行為與輸出——這正是當前 LLM 的弱項。

正確率的「複雜度落差」高達 4–5 倍。 另一份針對 AI 單元測試生成工具準確性的整理指出，在真實世界的複雜函式上，AI 生成測試首次嘗試正確率僅 12.69%；但在較簡單的合成 benchmark（如 2025 年的 ULT benchmark）上，正確率可達 48%–58%[S2]。這種懸殊的落差說明：許多宣稱高準確率的評測結果，可能是在對真實生產程式碼代表性不足的簡化題目上取得的，實務導入時不能直接套用。

執行回饋是最大槓桿，但也是成本來源。 靜態的「一次生成、不驗證」策略被形容為「生成然後祈禱」（generate and pray）[S2]。相對地，讓模型在沙盒中實際執行測試、觀察失敗結果並據以修正，能將相關程式碼生成任務的成功率提升 15 至 25 個百分點（K3Trans, 2025）[S2]。SWT-Bench 的排行榜資料可視為這個機制持續改良的縱向證據：2024 年 5 月的早期 agent（如使用 GPT-4 的 SWE-Agent）在 Lite 榜上只有 15.9% 的成功率與 26.5% 的覆蓋率增量；到了 2025–2026 年，結合更強執行回饋迴圈的方法如 e-Otter++、AssertFlip、OpenHands 搭配 GPT-5，乃至 2026 年的 DevstralTestGen（89.1% 成功率、57.6% 覆蓋率增量）與 TEX-T（Claude 4 Sonnet，87.0%／69.8%）、PatchTwin+Guard（GPT-5，Verified 榜 82.9%／78.7%），成功率已提升至八、九成的量級[S4]。這個演進軌跡直接印證了「執行導向」是準確率提升的主要驅動力，但每一輪執行—觀察—修正都意味著更多的 agent 互動輪次與 token 消耗，這正是 Artificial Analysis 特別將「每任務成本」與「token 使用量」列為與準確率同等重要的比較指標的原因[S3]。

Agent 骨架（harness）本身也是變數，而非只有底層模型。 Artificial Analysis 的一項對照實驗，固定使用同一個底層模型（Claude Opus 4.7），僅更換 agent 執行框架（Claude Code、Cursor CLI、Opencode），結果顯示分數會隨 harness 不同而變化[S3]。這說明「AI 測試生成的準確率」不能只歸因於底層 LLM 的能力，工具鏈如何組織執行迴圈、如何管理上下文與重試邏輯，同樣是決定性因素——也解釋了為何 SWT-Bench 排行榜上，同樣採用 Claude 系列模型的不同 agent 方案（如 e-Otter++ 對比 TEX-T），表現可以有顯著落差[S4]。

應用與實務啟示

對於將 AI coding agent 導入單元測試工作流的團隊，材料中的數據指出幾項實務含意。首先，不能把 AI 生成的測試套件當作覆蓋率的終點：TestGenEval 顯示即使是當前最佳模型，平均覆蓋率也僅略高於三分之一[S1]，意味著人工補強仍是必要環節，而非可選的「錦上添花」。其次，準確率與任務範疇高度相關：若團隊的目標是「重現一個已知 issue 的回歸測試」（如 SWT-Bench 的任務設定），現階段的頭部方案已能達到八、九成的成功率[S4]；但若目標是「從零打造一個高覆蓋率的完整測試套件」（如 TestGenEval 的任務設定），實際可期待的品質會低得多。團隊在評估工具或設定內部 KPI 時，應先釐清自己的實際使用情境對應哪一類 benchmark，避免用重現式測試的高分數去期待完整套件生成的品質。

第三，執行沙盒是投資報酬率最高的基礎設施。既然執行回饋能帶來 15–25 個百分點的提升[S2]，且 benchmark 進步軌跡與此高度吻合[S4]，團隊若要落地 AI 測試生成，優先建置的不是更強的模型，而是能讓 agent 安全、快速反覆執行與觀察結果的沙盒環境與 CI 整合。第四，維護成本的隱性戰場在「測試選擇器」與既有測試的脆弱性。市場上出現的 Testim、Mabl、Applitools、QA Wolf、Codium AI 等工具，其賣點集中在「自我修復」（self-healing）失效的選擇器與偵測視覺回歸[S6]，這反映出業界已經意識到：AI 生成測試若缺乏對程式碼變動的適應能力，長期維護成本會迅速侵蝕初期生成的效率紅利，因此 2026 年的產業焦點已從單純「生成」擴大到「生成 + 執行驗證 + 自我修復」的複合工具鏈[S6]。

觀點與趨勢判讀

材料中最值得留意的爭點，是不同 benchmark 對「AI 測試生成準不準」給出截然不同的答案：TestGenEval 顯示最佳模型覆蓋率僅 35.2%[S1]，另一份整理指出真實複雜函式的首次正確率僅 12.69%[S2]，但 SWT-Bench 榜單卻顯示 2026 年的頂尖方案成功率已逼近九成[S4]。這並非數據矛盾，而是任務定義本質不同：SWT-Bench 評估的是「針對一個已知、範圍明確的 issue 生成單一重現測試」，這是一個有清楚成功標準（修復前失敗、修復後通過）的收斂任務；而 TestGenEval 與一般覆蓋率導向的測試套件生成,要求模型在缺乏明確目標的情況下自主判斷「什麼值得測」與「邊界案例在哪裡」，是遠為開放且困難的任務。因此,任何宣稱「AI 測試生成已達 SOTA 水準」的說法，都必須先問清楚是在哪一種任務定義下取得的分數——這是解讀本領域所有效能宣稱時最重要的判讀濾鏡。

其次，「有效但不被信任」的落差（59% 認為有效、僅 29% 信任準確性）[S2]，加上七成工程主管認為 AI 正拖累應用品質[S2]，共同指向一個尚未解決的結構性問題：AI 測試生成目前更適合定位為「起草工具」而非「品質守門員」。這與覆蓋率／正確率數據吻合——當最佳模型的平均覆蓋率不到四成、複雜函式正確率僅一成出頭時，任何將 AI 生成測試直接視為品質保證的做法都存在風險。

最後，SWT-Bench 排行榜跨越近兩年的分數躍升軌跡（從 2024 年中的個位數／十幾趴，到 2026 年的八、九成）[S4]，顯示這個領域的進步速度確實很快，但進步的引擎主要是「執行回饋迴圈」與「agent 工程」的優化，而非單純的底層模型升級——Artificial Analysis 的 harness 對照實驗也佐證了同一模型換不同執行框架就能改變結果[S3]。這意味著未來競爭的重點很可能不再是「誰的基礎模型更強」，而是「誰的執行沙盒、重試策略與自我驗證機制設計得更好」。至於覆蓋率能否在可預見的未來突破當前三、四成的天花板，材料中並無直接證據支持樂觀預期，這仍是懸而未決、值得持續追蹤的問題。

摘要

大型語言模型的能力敘事長期以參數規模與單模型基準為中心，卻日益依賴檢索、程式執行與工具呼叫等外部模組。本文以系統性文獻綜述與三角佐證，考察知識時效、計算推理與行動執行三條能力外包軸線，並追蹤其如何在複合式 AI／多代理編排控制平面中被組裝。方法上以OpenAlex／arXiv 關鍵字池篩選 111 篇候選、納入 22 篇（A 級 21），對五項核心主張各以≥3 獨立來源交叉驗證。核心發現：可觀測的『前沿表現』常來自編排與外包介面，而非權重內封閉能力；單模型基準因此存在結構性測量錯位。本文論證應導入能力會計（capability accounting），把權重內與系統外能力分欄計量，作為研究評估與工程治理的共同語言。

引言

[李飛飛主筆]

當社群談論「前沿模型能力」時，視線常鎖在參數規模、預訓練算力與單次對話基準。ImageNet 時代教會我一件事：數據與基準能推動整個領域——但基準若量錯對象，整個領域會被錯誤激勵。今日 LLM 的可觀測躍升，愈來愈不像「權重內封閉智能」的單調函數，而像把知識時效、符號計算與環境行動卸載到系統邊界之外的組裝工程。

知識缺口在此：我們擁有豐富的 RAG、PAL、ReAct、Toolformer 與複合式 AI 藍圖文獻，卻缺少把這些模組統一命名為「能力外包」、並追問測量邊界如何被重劃的架構學敘事。研究問題因此是：（RQ1）知識／計算／行動三軸外包如何改變「模型能做什麼」的可觀測定義？（RQ2）編排控制平面如何把外包模組變成可交付系統？（RQ3）單模型基準與政策敘事如何因外包而結構性錯測？

本文貢獻預告三點：第一，提出能力外包作為橫斷文獻的架構語言；第二，以五項三角佐證主張連起技術譜系與企業編排；第三，在原創論點中提出「能力會計」雙欄帳，作為評估與治理的操作介面。這不是否定權重內學習的價值，而是拒絕把系統層增益誤記成模型神諭。

文獻回顧

[李飛飛主筆]

知識卸載：從參數記憶到檢索與生成式整合

Lewis 等人把參數記憶與非參數 Wikipedia 索引並置，確立 RAG 作為知識密集型任務的經典補償架構［來源：Lewis et al., 2020］。Gao 等人的綜述則顯示，LLM 時代的 RAG 變體已常態化：事實查詢與知識時效不再被預設為「更大模型就能記住」［來源：Gao et al., 2023］。Ai 等人把生成式資訊檢索（GenIR）推進一步，強調資訊生成與資訊綜合，並指出幻覺緩解依賴 grounding 與外部知識整合［來源：Ai et al., 2025］。Roffo 更直白地將時序知識斷層、數學不準與幻覺列為固有限制，並以 RAG／PAL／ReAct／LangChain 作為系統層解方［來源：Roffo, 2024］。

這條譜系對 human-centered 評估的含義是：使用者感知到的「模型很懂」，可能是索引新鮮度與檢索品質，而非參數內世界知識。若基準不拆開這兩層，公眾與政策會把系統服務誤讀成模型人格。

計算與行動卸載：程式執行時與工具迴路

Gao 等人的 PAL 把解算步驟卸載至 Python 直譯器，LLM 只負責編成可執行程式；Codex+PAL 在 GSM8K 上相對 PaLM-540B+CoT 約有 +15% 絕對準確率［來源：Gao et al., 2023］。Schick 等人的 Toolformer 以自監督學會何時呼叫 API，使 6.7B 模型在算術／事實查詢上可與更大模型競爭［來源：Schick et al., 2023］。Yao 等人的 ReAct 交錯推理軌跡與外部行動，在 ALFWorld／WebShop 提升絕對成功率約 34%／10%，並強調可診斷軌跡［來源：Yao et al., 2023］；Google Research 官方詮釋亦凸顯 Reason+Act 的人機對齊任務軌跡［來源：Yao et al., 2022 blog］。

這不是「提示詞小技巧」，而是把能力邊界從 logits 擴張到執行環境。對基準設計而言：禁止工具的封閉考試，與允許工具的開放任務，量的是兩種不同物件。

編排控制平面：外包模組如何變成系統

Wang 等人綜述 LLM 自主代理的感知—規劃—行動—記憶模組化，顯示「前沿能力」常以系統組裝體現［來源：Wang et al., 2024］。Kandogan 等人提出企業複合式 AI 藍圖：streams、agent／data registry、QoS 規劃器，明確主張從單體模型轉向複合系統交付［來源：Kandogan et al., 2025］。Song 等人的 Gradientsys 以 typed MCP＋ReAct 動態規劃做一對多派工，在 GAIA 上同時改善成功率、延遲與 API 成本［來源：Song et al., 2025］。Roumeliotis 等人把感知代理與元推理編排器分離，信任校準＋RAG 重評使零樣本準確率達 85.63%［來源：Roumeliotis et al., 2025］。Mouzouni 則把知識編排類比容器編排：權限、新鮮度、意圖路由［來源：Mouzouni, 2026］。

Krishnan 批評現行代理基準不足，呼籲兼顧效能、效率、穩健與安全的整體評估［來源：Krishnan, 2025］。Wang 等人指出失敗軌跡經品質控制亦可提升工具使用［來源：Wang et al., 2024］；指令混合會使某些類型提升一域卻傷害他域［來源：Wang et al., 2023］。這些證據共同指向：資料配方與編排策略是能力的一等公民，而非微調後記。

測量與社會敘事的錯位

Liu 等人證明長上下文中間位置資訊利用率崩潰，「塞進視窗」不是可靠的知識外包替代［來源：Liu et al., 2024］。Bubeck 等人的 GPT-4 早期探測常被用作 AGI 火花敘事，但其評估多為單模型互動［來源：Bubeck et al., 2023］。Bommasani 等人的加州前沿 AI 政策報告以 trust but verify 為倫理根，若能力高度依賴工具鏈，治理須覆蓋系統邊界［來源：Bommasani et al., 2025］。Naito 等人的行為實驗顯示：AI 預測權威感可窄化人類決策空間［來源：Naito et al., 2026］——能力敘事本身改變行為。Sengupta 等人的 Jais 顯示資料配方可重劃能力地理邊界［來源：Sengupta et al., 2023］；Shang 等人的 PB-LLM 則提醒模型內能力本身亦是異質資源配置［來源：Shang et al., 2023］。

結果與討論

[李飛飛主筆]

三軸外包的可觀測效應

結果一：知識軸上，RAG／GenIR 文獻一致顯示事實與時效能力可被卸載到非參數記憶與生成整合層［來源：Lewis et al., 2020；Gao et al., 2023；Ai et al., 2025］。這重寫了「模型知道什麼」：在部署中，它常常是「系統此刻檢索到什麼」。

結果二：計算軸上，PAL 與 Toolformer 證明符號／算術步驟可卸載至執行時或 API，使中型模型在特定任務上追趕甚至超越更大純 CoT 模型［來源：Gao et al., 2023；Schick et al., 2023；Roffo, 2024］。能力敘事若只報參數量，會系統性低估「執行時契約」的貢獻。

結果三：行動軸上，ReAct／多代理排程把環境互動編成可觀測軌跡，成功率與可診斷性同步上升［來源：Yao et al., 2023；Song et al., 2025；Yao et al., 2022 blog］。企業藍圖進一步把能力綁定到 registry、streams、QoS 與信任校準［來源：Kandogan et al., 2025；Roumeliotis et al., 2025；Mouzouni, 2026］。

測量邊界的結構性錯位

當 Bubeck 式單模型探測與「把文件塞進長上下文」的工程直覺並存時，Liu 等人的中間崩潰結果成為清醒劑［來源：Bubeck et al., 2023；Liu et al., 2024］。Krishnan 對代理基準的批評、Bommasani 對系統邊界治理的呼籲，以及 Naito 對預測權威感的行為證據，共同說明：錯測不只發生在實驗室分數，也發生在政策與個人決策空間［來源：Krishnan, 2025；Bommasani et al., 2025；Naito et al., 2026］。

實踐建議

[Yann LeCun主筆]

別再把「更大的接龍模型」當成唯一架構答案。工程上我建議三件事：

  1. 外包介面契約：對檢索、代碼執行、工具 API 分別定義 SLA、失敗語意與可觀測 span；把 MCP／registry 當一等基礎設施，而不是 prompt 附錄［來源：Song et al., 2025；Kandogan et al., 2025］。
  2. 雙欄評估儀表板：左欄＝裸模型封閉基準；右欄＝允許工具／檢索的系統基準；禁止用右欄分數宣傳左欄能力。這比再堆一個「AGI 探測」有用。
  3. 世界模型取向的長期補償：純文本接龍在物理常識與長期規劃上脆弱；外包與編排是務實補丁，但研究預算應保留給可預測世界狀態的架構（JEPA 路線的精神），而非無限 prompt 工程［來源：Roffo, 2024；Wang et al., 2024］。

開源權重有助複現外包介面實驗；封閉 API 若只公布「全能分數」而不公布工具圖，那是行銷，不是科學。

風險與限制

[Yann LeCun主筆]

風險一：工具失敗傳播——編排層把局部 API 錯誤放大成全域幻覺軌跡；信任校準若缺失，人類會過度信任錯誤工具鏈［來源：Roumeliotis et al., 2025］。風險二：權限與知識新鮮度外洩——Context Kubernetes 式治理若未落地，代理可能拿到錯權限的「正確答案」［來源：Mouzouni, 2026］。風險三：評估循環驗證——用同一工具增強系統既訓練又評測，會製造基準飽和假象［來源：Krishnan, 2025］。風險四：社會層面——能力敘事的權威感可能窄化人類想像的未來選項［來源：Naito et al., 2026］。

限制：本報告為二次文獻綜述，未做新的受控實驗；來源以英文明刊／預印本為主，產業內部失敗案例可能低報；2026 年若干預印本尚待同儕複核（標註於書目年份）。我不把這些限制當成否定外包命題的藉口——它們恰好說明：我們需要更好的系統級測量，而不是更大的 hype。

原創論點

[李飛飛主筆]

我要提出一個可操作的架構概念：能力會計（capability accounting）。把「模型會什麼」拆成兩欄帳本——權重內欄（parametric competence）與系統外欄（offloaded competence）。每一次產品宣稱、論文摘要或政策評估，必須標註分數記入哪一欄，以及外包介面的版本雜湊（檢索語料切割、工具 schema、編排器策略）。

為何這不是文字遊戲？因為 ImageNet 的教訓是：基準定義了研究注意力。若注意力只獎勵權重內欄的刷分，產業會低估檢索污染、工具供給鏈與編排錯誤對真實使用者的傷害；若注意力只獎勵系統外欄的演示，又會把基礎設施債務包裝成「模型變聰明了」。雙欄會計強迫披露：增益來自何處、失敗屬於哪一層、對誰負責。

獨立論斷一：在知識密集型部署中，未分欄的「模型正確率」在詮釋上不可識別——它混合了索引品質與參數記憶。獨立論斷二：PAL／Toolformer 類增益應計入執行時契約版本，而非基座參數量行銷。獨立論斷三：多代理 QoS／信任校準改變的是系統外欄的可靠度函數，用單代理零樣本分數外推企業編排風險屬範疇錯誤。獨立論斷四：對公眾溝通時，把系統外欄增益說成模型「具備 AGI 火花」，會透過權威感機制壓縮人類決策空間——這是 human-centered 不可接受的敘事外部成本。

能力會計不要求停下 scaling；它要求 scaling 與 offloading 的治理語言對齊。這才是我心中「技術服務人類福祉」在評估層的最小可行落地。

結論

[李飛飛主筆]／[Yann LeCun主筆]

我們回答 RQ1：知識、計算、行動三軸外包確已重寫可觀測能力定義，證據來自 RAG／GenIR、PAL／Toolformer、ReAct 譜系。RQ2：企業與多代理文獻顯示 registry、streams、MCP、信任校準構成外包模組的控制平面。RQ3：單模型長上下文、AGI 探測與未覆蓋工具鏈的政策敘事，存在結構性錯測與社會權威效應風險。

後續方向：（1）設計公開的雙欄基準套件；（2）對編排失敗做因果追蹤標準；（3）把能力會計寫入 frontier 政策的 verify 清單。限制已述：二次文獻、英語偏誤、預印本未決。

[李飛飛] 基準若量錯，人類福祉敘事會跟著歪。

[Yann LeCun] LLMs 可以是有用工具；別把它們的系統外掛，誤認成世界模型已經完工。

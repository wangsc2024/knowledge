GitHub Scout：Pydantic AI／Graph Tool

專案觀測摘要

  • pydantic/pydantic-ai（18212★，pushed 2026-07-05）：型別化 Agent 框架，pydantic-graph 為獨立 FSM 圖式函式庫，官方支援 Temporal/DBOS/Prefect/Restate 四種可插拔持久化執行後端；tool_result_validator 以 Pydantic model 逐欄位驗證工具引數，失敗時回饋具體錯誤給 LLM 重試。
  • dbos-inc/dbos-transact-py（1465★，pushed 2026-07-03）：資料庫支撐（Postgres）的輕量持久化執行，@DBOS.workflow 裝飾器包裝既有函式，無需新增常駐 workflow engine。
  • restatedev/restate（4113★，pushed 2026-07-03）：Rust 核心集中式持久化執行 runtime，需獨立部署常駐服務，基礎設施成本高於 DBOS。

改進提案

  1. P1｜tool_result_validator 欄位級錯誤回饋重試（來源 pydantic/pydantic-ai）：本系統 tools/local_toolcall_loop.py 原僅驗證 tool_call 引數是否為合法 JSON，未對照 schema 檢查必填欄位/型別。
  2. P1｜github-scout-review-policy topic_override 補齊（來源 pydantic/pydantic-ai）：SKILL.md 搜尋主題表含此主題但 review-policy.yaml 缺對應結構化欄位。
  3. P3｜持久化執行後端抽象化（來源 dbos-inc/dbos-transact-py）：四選一插拔後端模式，與本系統 2026-05-30 LangGraph 退役後的「純 Python + JSON checkpoint」精簡方向衝突，列長期觀察。

審查結論

  • 提案 1、2：feasibility_score=9、stability_score=8，皆為現有檔案的欄位級增量修改，無外部依賴新增，rollback 可用 git revert 或還原備份檔；已直接落實。
  • 提案 3：因與近期精簡決策（ADR-20260529-052 LangGraph 退役）方向衝突，且需引入資料庫/常駐服務等新基礎設施，不研擬落實方案，僅作 KB 觀察紀錄。

已落實項目

  • tools/local_toolcall_loop.py 新增 _validate_tool_args／_matches_json_type（純 stdlib），於 run_native_tool_loop 工具派發前驗證 required/type，失敗回饋具體欄位錯誤訊息；tests/tools/test_local_toolcall_loop.py 新增 5 個測試，全部 31 個測試通過（原 26 + 新 5）。
  • config/github-scout-review-policy.yaml 新增 topic_overrides.pydantic_graph_durable_execution（含 graph_orchestration_model／durable_execution_backend／tool_result_validation_model 三必填欄位），YAML 經 yaml.safe_load 驗證通過。

待人工審核項目

  • 無（本輪 P0/P1 提案均為低風險已直接落實；P3 觀察項目不需人工審核，僅供未來參考）。

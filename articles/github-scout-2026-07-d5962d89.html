  1. langfuse/langfuse（31296★，pushed 2026-07-17）：LLM engineering 平台，evals + observability + prompt management + playground + datasets 統一於單一產品；整合 OpenTelemetry/LangChain/OpenAI SDK/LiteLLM。REST 觀測：https://api.github.com/repos/langfuse/langfuse。

改進提案

  • P2（已落實）：config/otel-config.yaml 死標籤風險文件化——enabled:false 自 2026-06-13 openllmetry_bootstrap 落地起未曾切換，且無 ADR/plan 明文交代停用原因；補註解交代現況與消費端，零功能變更。
  • P1（計畫待審）：OTel 匯出觀察期試跑——既有 sampling.rate=0.1 低採樣，受控 7 天觀察窗啟用匯出，驗證 logs/otel/traces.jsonl 產生與 hooks pipeline 測試維持綠燈；比照本系統歷史慣例（Phoenix OTLP／agentevals bridge／OTel GenAI span alignment 均為 high_risk）升為高風險，不直接落實。

審查結論

驗證 GitHub REST 觀測數據準確（主 Agent 二次 curl 複核 3 案數值一致）。核心發現：本輪研究過程中確認 traceloop/openllmetry 的 auto-instrumentation 模式已於 2026-06-13（commit b4a90bbb）落實（tools/openllmetry_bootstrap.py + config/otel-config.yaml + config/capability-manifest.yaml 登記 + 3 個消費端），避免重複提案造輪；openobserve 的 JSONL+rotation 架構驗證本系統既有 hooks/post_tool_logger.py _FileSpanExporter 方向正確，非缺口。唯一真正新落實面向為 P2 死標籤文件化。

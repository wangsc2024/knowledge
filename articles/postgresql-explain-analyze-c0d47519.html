PostgreSQL EXPLAIN ANALYZE 解析報告

結論

PostgreSQL 的 EXPLAIN 命令主要用於展示查詢計畫，而 EXPLAIN ANALYZE 則會實際執行查詢並回報執行統計。對於會修改資料的指令（如 INSERT、UPDATE、DELETE），使用 EXPLAIN ANALYZE 會產生實際的資料變動。為了在不影響資料的情況下分析這些指令的執行計畫與效能，標準做法是將其包裝在事務中並於結束前執行 ROLLBACK。此外，透過 BUFFERS 選項可觀察 I/O 表現，並配合 FORMAT JSON 方便程式自動化解析。

核心主張

  1. 執行行為差異：EXPLAIN 僅產生預估計畫，不影響資料；EXPLAIN ANALYZE 會實際執行 SQL 指令。
  2. 資料安全保護：在執行 INSERT、UPDATE、DELETE、MERGE 或 CREATE TABLE AS 等具備副作用的指令時，必須使用 BEGIN; EXPLAIN ANALYZE ...; ROLLBACK; 結構，以確保資料不會被永久寫入。
  3. 效能診斷深度：

- 使用 BUFFERS 選項可以獲取共享區塊（shared blocks）的命中、讀取、髒污及寫入資訊，對於優化 I/O 密集型查詢至關重要。

- 使用 FORMAT JSON（或 XML、YAML）可產出機器可讀的格式，適合與外部分析工具結合。

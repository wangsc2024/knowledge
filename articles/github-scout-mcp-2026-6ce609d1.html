核心新發現：AI-hybrid 信任分模型

搜尋過程發現 sunnamed434/awesome-mcp-registry（僅 1★，未達本系統 500 星最低門檻，不列為正式 project）採用「AI-curated, self-updating directory」模式：

  • 0-100 信任分數 = 35% AI rubric（GPT-4.1-mini 依錨定評分標準逐案評估）+ 65% 確定性指標（maintenance / popularity / docs / security posture / community）
  • metrics 每週自動刷新；AI 評分每 90 天複核一次
  • 對照 tolkonepiu/best-of-mcp-servers（117★，「Updated weekly」排名列表，同樣未達門檻）— 顯示 MCP 生態近期出現多個「自動化週期性重評」的新興策展工具，但規模仍小

改進提案

P1（風險 medium，計畫待審）：本系統 tools/asset_accountability 的 value_score（config/asset-value-targets.yaml refs/recency/success 加權）目前純確定性計算，無質化 AI 判斷層，無法捕捉「文件品質」「程式碼可讀性」等面向。建議評估是否為 skill/tool 兩型別新增可選 AI-rubric 子分數（可複用既有 tools/kb_note_quality_scorer.py 四維度評分模式），與現有 value_score 混合而非取代。因涉及退役/改善判定演算法（影響全系統 4 類資產的問責結果），風險等級 high，改為輸出計畫至 docs/plans/github-scout-20260714-asset-value-ai-rubric-layer.md 待人工審核，不直接落實。

審查結論

P1 提案：feasibility_score=7、stability_score=6（因觸及既有 value_score 加權公式，需審慎驗證是否影響現有 improve-then-retire ledger 判定結果，未達步驟 9「低/中風險直接執行」標準，且命中 config/autonomous-harness.yaml execution_contracts 之 review_required_when：「proposal changes scheduler or interception behavior」相鄰語意——雖非直接改排程，但改動退役判準屬同等敏感度），故不直接落實，僅輸出計畫。

深度研究洞察簡報：LLM Self-Correction 內部失敗機制與 Confabulation 防範——對照 DDP self_heal 反思記憶設計

系列：agent-metacognition-selfcorrection（AI Agent 元認知與自我校正機制 × 認知科學理論映射）
階段：mechanism（foundation 已於 2026-07-06 完成）
日期：2026-07-11

摘要

本簡報推進 agent-metacognition-selfcorrection 系列至 mechanism 階段，聚焦「LLM self-correction 為何在缺乏外部回饋時失敗」與「記憶虛構（confabulation）防範設計原則」兩條主線，交叉比對 8 篇 A/B/C 級外部來源（含 arXiv 2606.05976、2507.02778、2604.22273v2、Nature s41586-024-07421-0 等）與 DDP 既有機制（config/memory-policy.yaml P1-P4 原則、tools/memory_fabrication_audit.py、tools/planner_executor/research_confabulation_guard.py、tools/auto_task_phase3_prep.py 的 memory_provenance 結構）。核心發現：self-correction 失敗的機制層根因是「addressability」（模型缺乏將自身思維子字串當作可指涉物件的能力）而非驗證能力不足；收斂性存在可量化邊界條件（ECR/EIR 比值）；「驗證修辭」與「驗證能力」是兩回事，84-100% 模型會寫「已驗證」卻不具備對應能力。DDP 現行 P1-P4 稽核邏輯命中多數外部共識，但屬事後批次稽核而非寫入時強制 gate，且 memory_provenance 的觀察/解釋分離結構在下游注入時被扁平化，削弱了本可提供的「可指涉把手」效果。萃取 7 項核心洞見、套用 2 組 primary 思考透鏡（Sam Altman、黃仁勳）+ 1 組 adversarial 透鏡（Taleb），提出 2 項具體可執行的低成本改善建議，已寫入系統改善 backlog。

---

核心洞見

洞見 1：Self-correction 失敗的真正機制是「addressability」，不是驗證能力不足

  • 理論主張：[A級] Self-Correction Illusion（arXiv:2606.05976）以位元組級相同的錯誤陳述、僅變換角色標籤做對照實驗：外部角色（user/tool）可被模型修正，標成自身 則被忽略。核心機制是模型缺乏將思維內子字串當作可指涉離散物件處理的學習模式；純粹的自我懷疑提示只帶來 0-23% 修正率，遠低於角色重標的 70%。
  • DDP 現況對照：tools/auto_task_phase3_prep.py:274-287 的 memory_provenance 欄位已隱含類似結構——把 observation（status/schema_validated/harness_trace_id）與 interpretation（topic/key_findings）拆成不同物件鍵，等同給模型一個可指涉的「把手」。但這個結構化拆分只在寫入時產生：templates/shared/preamble.md:191-198 讀取端僅用 memory_provenance.speculative 布林值做降權標記，下一輪 Agent 看到的仍是扁平化 key_findings 文字加 [speculative] 前綴，把結構化把手又攤平回無法指涉的連續文字。
  • 建議行動：preamble 記憶注入格式改為 [OBSERVED]: ... / [AGENT-INTERPRETED]: ... 兩個明確標記區塊，而非合併字串。
  • 證據來源：arXiv:2606.05976；tools/auto_task_phase3_prep.py:274-287；templates/shared/preamble.md:191-198

洞見 2：Self-correction 收斂性存在可量化邊界條件，DDP 目前無此類指標

  • 理論主張：[A級] Feedback Control 論文（arXiv:2604.22273v2）給出臨界不等式 ECR/EIR > Acc/(1-Acc)（錯誤修正率/錯誤引入率之比要大於當前準確率的機率比）；僅 EIR≈0% 的模型能持續改善，其餘呈振盪或單調退化。關鍵發現：84-100% 模型輸出「驗證修辭」，但只有真正低 EIR 能力的模型有效——驗證修辭 ≠ 驗證能力。
  • DDP 現況對照：tools/planner_executor/research_confabulation_guard.py 門檻是純時間型（耗時 <120s → 降級 partial），config/memory-policy.yaml:167-178 的 P3/P4 是單次二元判斷，缺乏跨輪次「修復是否製造新問題」的 EIR/ECR 型統計。
  • 建議行動：對 self_heal 每個 task_key 累計「修復後緊接觸發同類 backlog」比例（近似 EIR）與「修復後同類 backlog 未再現」比例（近似 ECR），持續超標時觸發降級或人工複查，而非只看單輪 post_fix_verify 通過與否。
  • 證據來源：arXiv:2604.22273v2；tools/planner_executor/research_confabulation_guard.py:13；config/memory-policy.yaml:167-178

洞見 3：訓練資料組成造成的盲點，對應 DDP 記憶注入永遠只看到成功範例

  • 理論主張：[A級] Self-Correction Bench（arXiv:2507.02778）指出訓練資料幾乎全是「無錯誤示範」，模型極少看過「錯誤→識別→修正」完整序列；插入「Wait」提示可平均降低 89.3% blind spot。
  • DDP 現況對照：config/memory-policy.yaml:189-198 的記憶回饋機制餵給下一輪 Agent 的多是成功/部分成功 run，結構性缺少「明確標示失敗嘗試+原因」的負例。
  • 建議行動：continuity run 記錄新增 failure_pattern_example 標記，preamble 注入時優先挑 1-2 筆「失敗→修正」配對並標成 [FAILURE-THEN-FIX EXAMPLE] 區塊。
  • 證據來源：arXiv:2507.02778；config/memory-policy.yaml:189-198；tools/results_self_heal.py:41-45

洞見 4：DDP P1-P4 原則命中多數外部共識，但屬事後稽核而非寫入時強制

  • 理論主張：[C級]/[B級] Constitutional AI 相關文獻與 CRITIC 均指出自我批判需搭配外部驗證機制，否則只是表面模式匹配；[A級] semantic entropy 論文（Nature s41586-024-07421-0）強調 confabulation 偵測應與其他幻覺類型分離處理。
  • DDP 現況對照：config/memory-policy.yaml:167-178 四原則（P1 觀察/解釋分離、P2 持久化前外部驗證、P3 標記推測性記憶、P4 限制回饋覆寫）由 tools/memory_fabrication_audit.py 落實稽核（_audit_rca_report／_audit_continuity_run），精準對應外部文獻「自我批判需外部錨定」原則，但屬獨立批次掃描腳本，未接入寫入路徑作 gate。
  • 建議行動：確認 memory_fabrication_audit.py 是否有排程呼叫（若無則屬死代碼風險），評估在 memory_provenance.speculative=true 且觸發 P4 時讓寫入路徑主動降級而非僅留標記。
  • 證據來源：Nature s41586-024-07421-0；config/memory-policy.yaml:167-178；tools/memory_fabrication_audit.py:60-165

洞見 5：research_confabulation_guard 的耗時 proxy 與「驗證修辭≠驗證能力」發現互補但覆蓋面不同

  • 理論主張：[A級] Feedback Control 論文的「驗證修辭」發現說明僅測耗時無法抓到「花了時間但輸出虛構驗證措辭」的隱蔽情況。
  • DDP 現況對照：research_confabulation_guard.py 只在 planner_executor v3 research task 路徑運作，memory_fabrication_audit.py 只在事後批次掃描，兩者互不相通。
  • 建議行動：為 research_confabulation_guard.py 增補文字層檢查，比照 memory_fabrication_audit.py:34-36 的 _FIX_CLAIM_MARKERS/_VERIFY_TEXT_MARKERS pattern，偵測「已驗證」等措辭缺乏證據錨點時標記疑似 confabulation。
  • 證據來源：arXiv:2604.22273v2；tools/planner_executor/research_confabulation_guard.py:13,51-53；tools/memory_fabrication_audit.py:34-36

洞見 6：語意分群偵測任意生成，可補強 DDP 純規則式 P1/P3 判斷（暫緩，成本較高）

  • 理論主張：[A級] semantic entropy 方法對多次生成做語意分群、算跨群熵值，偵測「流暢但錯誤且任意」的生成，無需人工標註。
  • DDP 現況對照：memory_fabrication_audit.py 的 P1/P3 是純結構式規則（有無 evidence 欄位、confidence 數值），不看內容語意跨 run 是否自相矛盾。
  • 建議行動：不建議短期實作（額外 LLM 呼叫成本高，違反機械優先階梯）；可先用機械層代理（同 task_key 短期 root_cause 文字相似度低於門檻）初篩，列為 optimization 階段候選方向。
  • 證據來源：Nature s41586-024-07421-0；tools/memory_fabrication_audit.py:60-99

洞見 7：DDP self_heal 雙 profile 分離已符合 CRITIC「驗證者與生成者分離」設計，屬既有優良實踐

  • 理論主張：[B級] CRITIC 與 PAG 研究指出同一模型身兼生成/評估/批判角色易複製相同盲點；角色交替或獨立驗證步驟可緩解。
  • DDP 現況對照：tools/self_heal_llm.py:15-16 已定義 self_heal_executor 與 self_heal_executor_recovery 雙 profile，加上 tools/repair/post_fix_verify.py、tools/repair/auto_rollback.py 的獨立驗證步驟，架構上符合「驗證者與生成者分離」。
  • 建議行動：無需改動，僅建議在後續報告中明確記錄為正面案例。
  • 證據來源：arXiv:2506.10406（PAG）；tools/self_heal_llm.py:14-16；tools/repair/post_fix_verify.py

多透鏡洞察

透鏡選擇與理由

本次 precompute（temp/insight-briefing-lens.json，rationale: task_profile:insight_briefing）選定 Sam Altman 與黃仁勳作為 primary 透鏡、Taleb 作為 adversarial 透鏡。適用理由：本主題本質是「系統能力邊界的量測與部署決策」——Sam Altman 的「快速部署反饋」與「compute 是否為瓶頸」心智模型適合框架化「該不該把 self-correction gate 前移到寫入時」的產品化取捨；黃仁勳的「demand-driven 創新」（先看 workload 再定義規格）適合評估 DDP 該優先建哪一層防護（文字層 marker vs 語意層 entropy）；Taleb 的懷疑主義與「skin in the game」則用來檢驗本簡報建議是否只是「表演式驗證」而非真正可驗證的機制。

框架化建議

以 Sam Altman 的快速部署反饋心智模型檢視：洞見 1（preamble 結構化標記）與洞見 5（文字層 marker 檢查）都是「先 ship 再迭代」型改動——低成本、可快速部署、能立即用真實 self_heal 執行資料驗證是否降低 confabulation 誤判率，符合「用戶反饋閉環」優先於閉門研究到底的決策啟發式。相對地，洞見 6（語意熵值分群）屬於「compute 是否為瓶頸」判斷下應延後的項目：額外 LLM 呼叫的規模化成本尚未被本次研究的實證基礎證成，貿然實作違反「先 ship 再迭代」原則。

以黃仁勳的 demand-driven 創新心智模型檢視：不應為「理論完備」而建語意分群這類重型基礎設施，而應先問「DDP 目前的 workload 是什麼」——本次研究顯示 memory_fabrication_audit.py 可能從未被排程觸發（洞見 4），這是比新增偵測能力更急迫的 workload 缺口；比照黃仁勳「全棧優化」邏輯，應先確保既有偵測層真正被啟用（軟體是否跟得上），再考慮疊加新的偵測維度，否則就是「不做無用規格」原則下應避免的過度工程。

反模式檢查

依 Taleb「拒絕的反模式」逐條檢視本產出：(1) IYI 檢查——本簡報若只停留在理論引用而未指出 DDP 檔案路徑與行號的具體對照，即落入「有學歷無實戰」的 IYI 模式；本次已對每項洞見附具體檔案路徑，通過此檢查。(2) 敘事謬誤檢查——洞見 1-3 引用的三篇 A 級論文對「self-correction 失敗根因」給出三種不同層級的解釋（addressability／訓練資料／動力系統），本簡報在「共識與分歧」一節明確標註三者不互斥而非強行編造單一因果故事，避免敘事謬誤。(3) 中間地帶檢查——洞見 6（語意分群）明確建議「暫緩」而非曖昧的「可以考慮」，避免 Taleb 所稱「不冷不熱」的真正危險策略。

透鏡盲區自陳

依 Taleb 誠實邊界第 4 點「500 頁的 100 頁洞察」：本簡報的核心貢獻（addressability 機制、ECR/EIR 邊界條件、驗證修辭≠驗證能力）具體且可驗證，但研究過程本身依賴子 Agent 單輪 WebSearch/WebFetch 蒐集，未對來源 4（Feedback Control 論文）給出的 ECR/EIR > Acc/(1-Acc) 公式做獨立數學驗證或復現實驗——這正是 Taleb「Skin in the Game」原則所質疑的：本簡報的建議者（研究 Agent）並未承擔建議失敗的直接後果，讀者採用「累計 EIR/ECR 統計」建議前，應先以 DDP 自身歷史 self_heal 資料做小規模回測，而非直接全面部署。此外，Sam Altman／黃仁勳透鏡的「決策啟發式」框架化建議屬第三人稱分析套用，非兩人本人對此議題的實際立場，調研截止 2026-06-01，之後動態未覆蓋。

共識與分歧

共識：多篇來源一致同意純粹的模型自我判斷（intrinsic self-correction）本質上不可靠，都指向需要某種形式的外部錨定——外部工具回饋、角色標籤重寫、或訓練資料介入；且都認同二元 pass/fail 型驗證不足以避免虛構。

分歧：對 self-correction 失敗根本原因的解釋層級不同——訓練資料組成（統計層）、表徵可指涉性（機制層）、動力系統穩定性（數學層）三者不互斥，可能是同一現象的不同切面，但建議的介入層級不同（prompt 層/呈現層/量測層），本簡報建議行動也依此分層排序（短期 prompt/呈現層 → 中期量測層 → 長期語意層）。

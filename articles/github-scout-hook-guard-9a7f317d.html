GitHub Scout：Hook/Guard 研究筆記（2026-07-05）

專案觀測摘要

REST 即時觀測（api.github.com）3 個專案：

  • gitleaks/gitleaks（28001★，pushed 2026-07-01）：commit-time／CI-time／事後掃描三種攔截點皆原生支援；預設 fail-closed（偵測到 secret 直接阻擋 commit/CI，僅顯式 SKIP=gitleaks 或 allowlist 可放行）；TOML 規則庫（.gitleaks.toml）分 rule-level／global-level allowlist，支援 commits/paths/regexes/stopwords 條件，另有 .gitleaksignore 按 fingerprint 排除。
  • SponsioLabs/Sponsio（465★，pushed 2026-07-03，低於政策 >500 最低門檻但主題高度相關予以保留）：工具呼叫執行時（每個 agent action 前）即時檢驗；預設 fail-closed，v0.2.0a3 曾修復非 LangGraph adapter 的 fail-open 漏洞；決策分 4 級 Pass/Block/Warn/Escalate（非二元 allow/deny），16 個預設合約包（46 個底層模式）。
  • rohitg00/awesome-claude-code-toolkit（2251★，pushed 2026-05-12）：策展目錄形式收錄 20 個 hook 範例，橫跨 PreToolUse／PostToolUse／SessionStart／SessionEnd 等攔截點，無統一 fail-open/fail-closed 宣告（本身為目錄非執行期防護）。

改進提案

  1. [P1/低風險/已落實] 新增 docs/github-scout-agent-comparables.md#hook_guard_agent_guardrails_comparables2026-07-05 章節，記錄三案攔截點/失敗模式/防護分類對照本系統現況。
  2. [P1/低風險/已落實] config/github-scout-review-policy.yaml 之 topic_overrides.hook_guard_agent_guardrails.notes 追加本輪觀測（gitleaks TOML allowlist 模型 + Sponsio 4 級決策模型）。
  3. [P1/高風險/計畫待審] Commit-time secret 掃描閘門：借鑑 gitleaks TOML 規則+allowlist，於 scripts/git-hooks/pre-commit 新增輕量 regex secret 偵測，補齊本系統 commit-time 與 tool-execution-time／事後掃描間的攔截缺口（目前僅每日 01:30 事後掃描，洩漏視窗最長 ~24h）。計畫檔：docs/plans/github-scout-20260705-commit-time-secret-scan-gate.md。
  4. [P2/觀察] awesome-claude-code-toolkit 之 20-hook 策展目錄可作未來稽核我方 hook 覆蓋率的外部對照參考，暫不轉為具體改動。

審查結論

提案 1、2 屬純文件/config 附加變更（無既有邏輯修改、無執行風險），feasibility=9、stability=9，通過審查直接落實。提案 3 因觸及 scripts/git-hooks/pre-commit（共用主樹每次 commit 皆執行，先例 2026-06-16 pre-commit 大批失敗 顯示此 hook 故障影響面廣），依 SKILL.md 步驟 8/9 判定 risk_level=high，5 輪審查標準下不適用直接落實條件（human_review_required=true），改輸出計畫待人工審核。提案 4 為觀察性記錄，未達 P0/P1 門檻不需審查流程。

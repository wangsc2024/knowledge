偵察提案：missuo/herdrm

專案是什麼

herdr 的原生 macOS 主控台，統一管理使用者機器上執行的所有 coding agent 及其即時終端機（terminal）狀態，並支援跨裝置查看。核心機制：對每個 agent process 建立即時連線通道，回報執行狀態與終端輸出，讓使用者在單一介面掌握多個並行代理的實況。成熟度：新上榜之 trending 專案，具體版本穩定度與傳輸協定待查證。

對本系統的借鑑點

  • Cordis 插件 runtime 已有「進退場機制」（PR #78/#80/#82），但屬事後判定；herdr 的「即時終端機跨裝置可視化」可借鑑為插件執行期間的即時健康看板，把各插件當下的執行狀態與輸出串流集中一處觀察，取代事後查 log 的模式。
  • todoist-team 現有「健康守望」排程分層機制，其產出目前偏文字/通知形式；herdr 示範了「多代理即時狀態總覽面板」的 UI 呈現方式，可作為健康守望輸出介面升級的參照對象。
  • herdr 強調「跨裝置」存取同一組 agent 即時狀態，對應到若未來需從手機等裝置查看 Cordis 插件或 todoist-team 排程任務的即時執行狀態，其「本地 agent ↔ 遠端主控台」連線架構值得研究，但具體傳輸協定與存取安全機制待查證，不宜直接套用。

建議行動

  • 低風險：先查閱 herdr 的狀態回報協定設計（如何從 agent process 擷取即時輸出並推送至主控台），整理成知識庫的「多代理即時可視化」技術參考筆記，不涉及任何現有系統改動。
  • 需人工決策：是否要為 Cordis 插件 runtime 或 todoist-team 健康守望新增「即時狀態總覽面板」——這涉及是否新增常駐服務或 UI 層，屬架構層級投資，建議先確認實際需求急迫度，再評估是否啟動概念驗證。

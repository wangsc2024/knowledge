GitHub Scout：執行沙箱 × 瀏覽器工具鏈（2026-07-12）

專案觀測摘要

本輪 REST 即時觀測 3 個專案（皆與近 7 天既有 github_scout 主題不重複）：

  • daytonaio/daytona（72221★，pushed 2026-07-09）：OCI/gVisor 容器隔離執行沙箱，冷啟<90ms，不支援 GPU passthrough；純 execution_environment_boundary，無瀏覽器/桌面工具層。新發現：2026-06 production 程式碼已閉源，原 repo 僅維持公開但不再維護，長期依賴風險升高。
  • microsoft/playwright-mcp（34968★，pushed 2026-07-09）：Playwright MCP server，純 tool_api_boundary。--allowed-origins/--blocked-origins 官方文件明言非安全邊界，可被 DNS rebinding／HTTP redirect 繞過（CVE-2025-9611，已於 0.0.40 修補）。
  • browserbase/stagehand（23462★，pushed 2026-07-11）：雙層邊界正例。execution_environment_boundary＝Browserbase 雲端 ephemeral Linux VM（獨立 fs/network/process tree，30 分鐘閒置自動銷毀）；tool_api_boundary＝全流量經 proxy 強制 domain allowlist（allowManagedDomainsOnly 未知網域靜默阻擋），敏感值以變數名稱替代不進 LLM context。

三案共同印證 deny-by-default 網域邊界為業界慣例。

改進提案

  1. P1（已落實，低風險）：於 config/github-scout-review-policy.yaml 之 topic_overrides.sandbox_runtime_fusion.notes 與 config/autonomous-harness.yaml 之 guardrail_surface_annotations.coverage_gaps 補充本輪三案觀測；於 docs/github-scout-agent-comparables.md 新增 sandbox_runtime_fusion_comparables_2026-07-12 對照表章節。純文件/config 觀測補充，不變更任何執行行為。
  2. P1（既有高風險計畫，本輪補充證據）：docs/plans/github-scout-sandbox-curl-allowlist.md（2026-05-31 建立，狀態待人工審核）追加「補充觀測（2026-07-12）」章節——stagehand 的統一 proxy 攔截模式回應該計畫審核要點「是否需對 WebFetch 做相同限制」；playwright-mcp 的 CVE-2025-9611 佐證純字串域名比對之繞過風險，建議新增 redirect/IP 直連繞過測試案例。因實際落實仍需修改核心攔截層 hooks/pre_bash_guard.py，維持 risk_level=high 與 plan_ready 狀態不變，未自動執行。

審查結論

提案 1：feasibility_score=9、stability_score=9（均 ≥7 通過標準），1 輪審查通過。採納原因：config-only 補充觀測，不涉及 guarded_operations 或 human_review_gates.high_risk_paths；風險：無（純新增陣列元素，向後相容）；rollback：git revert 對應 3 個檔案變更。

提案 2：feasibility_score=7、stability_score=7（文件補充部分達標），1 輪審查通過；但落實本體（修改 pre_bash_guard.py）因 execution_contract.human_review_required=true 依規則不可直接自動落實，維持 plan_ready。

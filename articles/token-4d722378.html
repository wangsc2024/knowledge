摘要

引言

[李飛飛主筆] 我教會自己看 AI 進步的方式，是先問「這對誰有影響」，再問「技術本身多先進」。多代理編排目前的敘事幾乎都是後者——更多代理、更複雜拓撲、更高任務成功率——卻很少有人問：誰在承擔中間的帳單？一個日均處理兩千張工單的客服 Agent，團隊原本估算月成本 800 美元，三週後帳單飆到近 6,000 美元 [來源：碼哥字節, 2026]，這不是個案的工程疏失，而是本研究要指出的結構性知識缺口：多代理系統的成本、延遲與可靠性並非「規模化的副作用」，而是編排層架構選擇本身的直接後果。

Anthropic 公開承認，其研究系統的多代理配置消耗約為單一聊天互動 15 倍的 token [來源：Anthropic, 2025]，這個數字若只被當成「多代理比較貴」的軼事，就會錯失後面的系統性論證：token 消耗需要經濟學分析而非技術修補 [來源：Chen et al., 2026]；拓撲設計本身是可調的成本槓桿 [來源：Cai et al., 2025]；延遲不是線性疊加而是透過平行呼叫複合 [來源：Elhaimeur & Chrisochoides, 2026]；企業規模擴張時路由品質會系統性衰退 [來源：Gillespie & Perry, 2026]。這四條證據線各自成立，但少有文獻將它們並置檢視其共同結構。

本研究的研究問題為：（RQ1）多代理系統相較單代理系統的成本倍增，是否為可預期的架構常態而非個案？（RQ2）拓撲與骨幹設計選擇，能否在相同預算下產生可驗證的效能差異？（RQ3）可觀測性與自癒基礎設施，應被視為選配的維運投資，還是編排層不可迴避的架構成本三角第三頂點？本研究貢獻在於：以 25 篇外部來源三角佐證五項核心主張，提出「成本感知拓撲優先於能力堆疊」的設計原則，並指出隱藏成本三角（token/延遲/路由）如何與可觀測性投資共同決定多代理系統能否真正服務其使用者。

文獻回顧

[李飛飛主筆] 本節依五個主題群組綜述 25 篇納入文獻。

(a) Token 成本量化與經濟學框架

Anthropic 工程部落格首次以生產數據承認：「代理本身消耗約 4 倍於聊天互動的 token，多代理系統則達 15 倍」[來源：Anthropic, 2025]，並指出 token 用量本身可解釋 80% 的效能差異——但這是以整體架構優於單代理 Opus 4 達 90.2% 為代價換來的。Chen 等（2026）首篇統整電腦科學與經濟學視角的 Token Economics 綜述，主張「token 已成為 Agentic AI 的核心經濟原語」[來源：Chen et al., 2026]，並將消耗依單代理優化、多代理協調摩擦、生態系壅塞、安全性四層系統化——這是本文選擇將「隱藏成本」定位為架構問題而非工程細節的關鍵文獻依據。

中文語境的實證案例補強了這個論點的急迫性：碼哥字節（2026）記錄 Claude Opus 4.7 新 tokenizer 使同一文本 token 數增加最多 35%，某客服 Agent 月成本從估算 800 美元飆升至 6,000 美元 [來源：碼哥字節, 2026]；WLB 對 Anthropic 案例的中文解讀進一步指出，「砸夠多 token 就能解決問題——但這不經濟，需要架構設計來提高 token 效率」[來源：WLB, 2025]。來順（2026）的優化指南則提供了應對方向的量化證據：七大策略、30+ 技術可將成本降低 30-70%、延遲降低 40-60%，同時維持 85% 以上品質 [來源：來順, 2026]。

(b) 拓撲/骨幹設計優化

若 token 消耗是可調變量，拓撲設計就是主要調節旋鈕。Cai 等（2025）的 AgentBalance 提出兩階段設計——先以 LLM pool matching 選定異質 agent backbone，再自適應生成 latency-aware 溝通拓撲，在相同 token 成本預算下取得最多 10% 效能提升，在相同延遲預算下取得最多 22% 效能提升 [來源：Cai et al., 2025]。這證明拓撲選擇並非事後優化，而是與骨幹選型同等重要的一階設計決策。

主要框架供應商的官方文件印證了拓撲多樣性已成為產業共識：Microsoft Semantic Kernel 編目 Concurrent、Sequential、Handoff、Group Chat、Magentic 五種拓撲，將拓撲選擇定位為「獨立於底層代理溝通/協調實作的技術無關設計決策」[來源：Microsoft, 2025]；OpenAI Agents SDK 直接對比 LLM 驅動與程式碼驅動兩種編排，主張「程式碼編排以彈性換取決定性的速度、成本與效能」[來源：OpenAI, 2025]；Google ADK 則結合確定性工作流控制器與 LLM 驅動動態轉移的階層式組合 [來源：Google, 2025]。LangChain（2026）的比較部落格進一步量化四種模式的成本差異：具狀態模式可在重複請求上節省 40-50% 呼叫次數，支援平行的模式在跨領域查詢上可削減 67% token [來源：LangChain, 2026]。AWS Bedrock 的 supervisor/collaborator 階層式拓撲則強調清晰角色邊界對編排品質的必要性 [來源：AWS, 2025]。

(c) 延遲複合效應實證

延遲是隱藏成本三角中最少被量化的一角。Elhaimeur 與 Chrisochoides（2026）對四代理 Gemini 2.5 Flash 教學系統跨併發層級實測 3,000+ 請求，證實「每個查詢觸發的多個並行 API 呼叫，其延遲會透過 parallel-phase-maximum 效應複合，此為單代理系統所不具備」[來源：Elhaimeur & Chrisochoides, 2026]。這個實證發現與 Anthropic Agent SDK 官方文件的設計主張形成對照——後者將平行、獨立 context 的子代理描述為「有助於提升輸出品質與縮短完成時間」的正面權衡 [來源：Anthropic, 2026]，但未揭露其延遲複合的代價結構。Dhanyamraju 等（2026）跨 208 個企業場景的比較顯示，規模（而非任務複雜度）主導編排效能衰退，而 Task Manager 元件可將高優先隊列延遲降低 14-75% [來源：Dhanyamraju et al., 2026]——顯示延遲管理需要顯式的架構元件，而非依賴拓撲本身自然收斂。

(d) 企業規模路由衰退

Gillespie 與 Perry（2026）在 110-agent、584-tool 的企業目錄上跨三個前沿模型測試單步路由，發現目錄規模從 10 擴至 110 個 agent 時，未明確指定請求的路由 F1 下降 16-23 個百分點，embedding-based shortlisting 僅能回補 10-17 個百分點 [來源：Gillespie & Perry, 2026]。這項發現與 Dhanyamraju 等的規模效應相互印證，顯示路由品質衰退是編排層的「規模化稅」而非個別實作缺陷。80aj（2026）從中文技術社群視角補充了實務因應方向：「傳統硬編碼拆分方案會使工作流數量呈指數級膨脹造成維護災難」，主張以動態路由取代硬編碼，依任務複雜度決定是否執行後置校驗 [來源：80aj, 2026]。

(e) 可觀測性與自癒基礎設施

若成本、拓撲與延遲構成隱藏成本三角的三個頂點，可觀測性則是使前三者可被量測、進而管理的必要基礎設施——但本身亦是成本。Dong 等（2024）的 AgentOps 分類法系統化界定 LLM agent 生命週期中須被追蹤的產物與資料 [來源：Dong et al., 2024]；Babu 與 Agrawal（2026）的自癒編排層以 monitor-detect-diagnose-recover-verify 迴圈，將任務成功率推升至 98.8%，優於單純重試（94.5%）與完全重規劃（93.8%）[來源：Babu & Agrawal, 2026]。Owotogbe（2025）將混沌工程引入多代理系統，主動注入幻覺、代理故障等問題以在生產模擬環境系統性揭露脆弱點 [來源：Owotogbe, 2025]；Adimulam 等（2026）則從整合視角提出涵蓋規劃、政策執行、狀態管理與可觀測性的統一編排架構 [來源：Adimulam et al., 2026]。這四篇文獻共同指出：可觀測性與自癒不是「加分項」，而是把前述三個成本頂點轉化為可管理工程問題的必要投資——但這項投資本身必須被計入總體擁有成本。

研究方法

[Yann LeCun 主筆] 方法論要誠實：本研究是證據包的二次綜述，不是新實驗，這點必須說在前面。檢索以三組英文關鍵詞（large language model architecture、AI agent orchestration、frontier model capabilities）驅動 arXiv/OpenAlex/Semantic Scholar 機械收割，加上中文技術社群補充搜尋，候選池 63 篇（phase0_candidates.json 為 SoT）。納入準則：（1）2024-2026 年發表；（2）與多代理編排的成本、拓撲、延遲或路由直接相關；（3）具可驗證 URL；（4）非 KB 來源。排除：negative_topics 已覆蓋的 19 個主題變體、無摘要之 stub、重複 URL。

來源分級：A=同行評審論文/arXiv 預印本（9 篇），B=官方技術文件/評測（7 篇），C=產業部落格/評測/社群討論（9 篇），中文來源 4 篇。最終納入 25 篇，滿足 min_a_tier_sources≥8 與 min_total_sources≥20 之 Tier S 門檻。

結果與討論

[Yann LeCun 主筆] 以下呈現五項三角佐證主張的綜合結果，並討論其對編排層設計決策的含義。

R1：多代理系統的 token 成本倍增（約 15 倍）是架構常態，非個案

Anthropic 的生產數據（15 倍）[來源：Anthropic, 2025]、Chen 等的經濟學框架化 [來源：Chen et al., 2026]、以及碼哥字節記錄的實際客戶案例（估算 800 美元→實際 6,000 美元，8 倍落差）[來源：碼哥字節, 2026] 三線獨立指向同一結論：token 倍增不是配置錯誤，是多代理協調本身的算術後果——每次子代理呼叫都攜帶完整 context 重建成本。已驗證✅（S10, S2, S22）

R2：骨幹-拓撲設計選擇能在相同預算下顯著改善效能，拓撲並非中性

AgentBalance 的實測數字（相同 token 預算下 +10%，相同延遲預算下 +22%）[來源：Cai et al., 2025] 不是孤例——Semantic Kernel 的五拓撲分類學 [來源：Microsoft, 2025] 與 LangChain 對四種模式的成本量化（有狀態模式省 40-50% 呼叫、平行模式省 67% token）[來源：LangChain, 2026] 共同證明：拓撲是可調的一階設計變量，而非「先寫功能、後選架構」的次要決策。已驗證✅（S1, S13, S16）

R3：延遲透過平行呼叫產生複合效應，非單代理系統所具備

Elhaimeur 與 Chrisochoides 的四代理教學系統實測 3,000+ 請求證實 parallel-phase-maximum 效應 [來源：Elhaimeur & Chrisochoides, 2026]；Dhanyamraju 等跨 208 場景的比較顯示規模主導效能衰退而非任務複雜度 [來源：Dhanyamraju et al., 2026]；Google ADK 官方文件將長時間執行/非同步工具支援列為延遲管理的必要機制 [來源：Google, 2025]，間接印證延遲若不顯式管理便會自然複合。已驗證✅（S3, S8, S15）

R4：企業目錄規模擴張，路由品質系統性衰退——規模化稅而非實作缺陷

Gillespie 與 Perry 在 110-agent、584-tool 目錄上的實測（F1 降 16-23 個百分點）[來源：Gillespie & Perry, 2026] 與 Dhanyamraju 等的規模效應 [來源：Dhanyamraju et al., 2026] 相互印證；80aj 從中文技術社群視角補充實務因應——動態路由取代硬編碼拆分 [來源：80aj, 2026]。三者共同定義：路由衰退不是「模型不夠聰明」，是目錄規模本身的架構稅。已驗證✅（S4, S8, S24）

R5：可觀測性與自癒機制是隱藏成本三角的第三頂點，而非選配維運投資

Babu 與 Agrawal 的自癒編排層將任務成功率推升至 98.8% [來源：Babu & Agrawal, 2026]；Owotogbe 的混沌工程主動注入故障以系統性揭露脆弱點 [來源：Owotogbe, 2025]；Dong 等的 AgentOps 分類法界定生命週期追蹤的必要產物 [來源：Dong et al., 2024]。這三篇共同指出：可觀測性投資不是「錦上添花」，是把 R1-R4 揭露的成本轉化為可管理問題的先決條件——但這項投資本身消耗工程資源，必須計入總體擁有成本。已驗證✅（S5, S6, S9）

實踐建議

[Yann LeCun 主筆]

  1. 先量拓撲再堆代理：部署前用 AgentBalance 式的 backbone-then-topology 方法論畫出成本-延遲曲線，而非直接套用某個框架的預設拓撲 [來源：Cai et al., 2025]。
  2. 把 token 消耗當財務指標追蹤，不是技術副產品：採用 Chen 等的經濟學分層框架，區分單代理優化、協調摩擦、生態壅塞三層成本 [來源：Chen et al., 2026]；參考來順的優化指南可望降本 30-70% [來源：來順, 2026]。
  3. 路由目錄規模化前先做 embedding-based shortlisting：Gillespie 與 Perry 的數據顯示此法可回補 10-17 個百分點的 F1 損失 [來源：Gillespie & Perry, 2026]。
  4. 可觀測性與自癒是上線前置條件，不是上線後補強：Babu 與 Agrawal 的 98.8% 成功率建立在監控-偵測-診斷-復原-驗證的完整迴圈上 [來源：Babu & Agrawal, 2026]，局部監控無法複製此結果。
  5. 拓撲選型前先跑混沌工程壓力測試：Owotogbe 的方法論可在生產前暴露代理間通訊失效等問題 [來源：Owotogbe, 2025]。
  6. 單代理基線不可省略：與拓撲設計決策同時，應保留可比較的單代理錨點，用以驗證多代理架構的邊際效益是否值回 15 倍 token 成本 [來源：Anthropic, 2025]。

風險與限制

[Yann LeCun 主筆]

  • 成本-效能曲線非線性且框架依賴：AgentBalance 的 10-22% 增益是在特定任務與骨幹選型下取得，不保證跨框架遷移 [來源：Cai et al., 2025]；CrewAI vs LangGraph 的獨立基準顯示同任務複雜度下框架完成率差距可達 8 個百分點以上（62% vs 54%）[來源：Golchian, 2026]，選型本身即是風險來源。
  • 產業敘事與實證證據存在張力：Cognition AI 主張多代理編排「目前僅在輔助代理貢獻智慧而非直接寫入時才真正有效」[來源：Cognition AI, 2026]，與部分框架供應商的階層式拓撲推廣論述形成對照，企業決策者須留意廠商敘事與獨立實測的落差。
  • 社群一手經驗提出的警示不可忽視：Hacker News 討論串明確警告「若單代理基礎未打好，擴展到多代理後會失控並燒掉更多 token」[來源：HN 社群, 2026a]，另一討論串則指出「編排增加的是平行性而非一致性，代理數量越多假設漂移越嚴重」[來源：HN 社群, 2026b]——這兩條一手實務證據雖屬 C 級來源，但與 A 級論文的延遲複合、路由衰退發現方向一致，強化了結論的外部效度。
  • 本研究限制：author 段依契約禁止補抓，25 篇來源以 2024-2026 年英文 arXiv 預印本與中英文產業部落格為主，未涵蓋企業內部生產數據（如具體 SLA 違約率或內部成本歸因模型）；Galileo Agent Leaderboard 雖提供跨模型成本-效能基準 [來源：Galileo AI, 2025]，但其 100 個合成情境未必代表所有產業垂直場景——待驗證⚠️。

原創論點

[李飛飛主筆] 我要把話說清楚，本文主張：多代理系統的「規模化」論述，長期把成本、延遲與路由品質包裝成「暫時的工程摩擦」，但本研究的五項證據指向一個更根本的判斷——這些摩擦本身就是架構的一部分，不會隨著模型變強而自然消失。

當一個客服團隊的月度帳單從估算的 800 美元飆升到 6,000 美元 [來源：碼哥字節, 2026]，當企業代理目錄從 10 個擴大到 110 個就損失 16-23 個百分點的路由準確率 [來源：Gillespie & Perry, 2026]，繼續用「這是 early-stage 工具鏈的成長痛」來解釋，就是在迴避一個更不舒服的事實：多代理編排的成本結構，從第一天就內建在其架構選擇裡。我提出以下四項原創判斷：

第一，隱藏成本三角（token/延遲/路由）不是三個獨立問題，是同一個架構決策的三個投影。 AgentBalance 之所以能同時改善效能與降低成本 [來源：Cai et al., 2025]，正是因為它把骨幹選型與拓撲設計視為單一決策空間——這暗示分開優化 token、延遲、路由三者，本質上是在同一個問題上做三次局部最佳化，注定次優。

第二，可觀測性投資的報酬率被系統性低估，因為它的效益只在失敗時才顯現。 Babu 與 Agrawal 的自癒編排在受限復原預算下優勢更明顯（94.0% vs 85.3%/88.2%）[來源：Babu & Agrawal, 2026]——這個數字的重要性不在平均情境，而在最壞情境：當系統壓力最大時，沒有可觀測性的架構會直接崩潰，有可觀測性的架構會優雅降級。這是我從 ImageNet 學到的另一課：基準與工具不該只在順境被檢驗。

第三，「規模化」一詞本身在多代理語境下是誤導性的比喻。 單體 LLM 的規模化（更多參數）確實帶來近似平滑的能力曲線；但多代理系統的「規模化」（更多代理、更大目錄）帶來的是 Gillespie 與 Perry 記錄的路由品質斷崖式衰退 [來源：Gillespie & Perry, 2026] 與 Elhaimeur 及 Chrisochoides 記錄的延遲複合效應 [來源：Elhaimeur & Chrisochoides, 2026]——這不是同一種數學，借用同一個詞彙會系統性誤導決策者的預期。

第四，誰承擔這筆隱藏工程稅，決定了多代理技術的公平性邊界。 有能力雇用專職 AgentOps 團隊、跑得起混沌工程壓力測試的組織 [來源：Owotogbe, 2025]，能把 R1-R5 的成本內化為可控的工程投資；沒有這些資源的中小型團隊，只能在帳單飆升後才發現問題 [來源：碼哥字節, 2026]。這不只是效率問題，是准入門檻問題——若隱藏成本架構持續被淡化為「細節」，多代理編排的實務能力將進一步向已有可觀測性基礎設施的大型組織集中。

這四項判斷共同指向一個設計原則：成本感知拓撲優先於能力堆疊。 在追問「要不要加一個代理」之前，應先問「這個拓撲決策會把我推向隱藏成本三角的哪個頂點，而我是否有能力觀測並管理它」。

結論

本研究以 63 篇候選、25 篇納入文獻，三角佐證五項核心主張，回答三個研究問題：

RQ1（成本倍增）：是。Anthropic 的 15 倍 token 消耗、Chen 等的經濟學框架化、與碼哥字節記錄的 8 倍實際落差案例三線一致，證實多代理系統的成本倍增是架構常態而非個案異常。

RQ2（拓撲效益）：是。AgentBalance 在相同預算下取得 10-22% 效能增益，證明骨幹-拓撲設計是可調的一階變量；但 CrewAI vs LangGraph 的框架間差異（8 個百分點以上）顯示這項效益高度依賴具體實作，不能無條件遷移。

RQ3（可觀測性定位）：應被視為架構成本三角的第三頂點，而非選配維運投資。自癒編排在受限預算下的優勢（94.0% vs 85.3%/88.2%）證明其報酬率集中於最壞情境，傳統平均情境的 ROI 計算會系統性低估其價值。

後續研究方向：（1）建立跨框架的成本-延遲-路由三維標準化基準，取代目前分散於個別論文的單點量測；（2）將 Gillespie 與 Perry 的企業路由衰退方法論延伸至非英語/多語言工具目錄場景；（3）量化可觀測性投資的邊際報酬曲線，以回答「多少監控才足夠」的實務問題。本研究限制在於：25 篇來源以英文 arXiv 預印本與中英文產業部落格為主，未涵蓋企業內部生產數據與具體 SLA 違約率，結論的產業垂直普適性有待更廣泛的實證驗證。

GitHub Scout：Agent 架構主題（LRU 最久未觸及 18 天，距 07-29）

專案觀測摘要

  • microsoft/agent-framework（12830★，pushed 2026-08-15，+233/11天）：graph-based workflow orchestration（sequential/concurrent/handoff/group patterns），Python+.NET。state_strategy：checkpointing + streaming + thread/session 持久化。human_review_model：interrupt-point 細粒度化——executor 送訊息至 RequestPort → 觸發 RequestInfoEvent（自訂 payload 或工具核准專用 ToolApprovalRequestContent）→ workflow 暫停直到 SendResponseAsync 回應。既有觀測之 approval_mode 為整體旗標，RequestInfoEvent 為單一工具呼叫級細顆粒度機制，兩者並存互補。
  • restatedev/restate（4303★，pushed 2026-08-14，+21/4天）：durable execution 基礎設施（非 agent 框架本體）。state_strategy：invocation journal 重放，崩潰後從已完成步驟繼續。human_review_model：signal-based awakeable——workflow 暫停等待某 ID 被 resolve，該唯一 ID 即冪等去重鍵，防止同一核准重複送達造成 double-resume。

改進提案

  1. P2（medium effort）：評估是否需支援單一工具呼叫級（而非整個變更提案級）人工核准暫停（RequestInfoEvent 啟發），若需要須設計對應 idempotency key 與 anti_stall_policy 整合方式。backlog_github_scout_20260816_190847039670。

審查結論

核心發現（驗證性研究，非新缺口）：業界 durable execution 平台（Temporal signal ID／Inngest match／Restate awakeable ID）對 HITL 核准訊號普遍要求顯式冪等去重鍵。對照本系統 config/autonomous-harness.yaml：execution_contracts.idempotency.key_fields（trace_id/task_key/operation_name/attempt，L162-164）已涵蓋 4 類受管操作冪等去重；human_review_gates.anti_stall_policy.authorization_matrix（L191-195）依 risk_tier 設 max_wait_minutes + default_decision，屬 bounded_wait 形態的 signal-based HITL，與業界模式同構。驗證既有設計方向正確。

次要發現：RequestInfoEvent/ToolApprovalRequestContent 之工具呼叫級核准粒度細於本系統現行 proposal 級，因涉及 harness 核心決策路徑，列 P2 backlog 待人工評估，非本輪立即行動。
